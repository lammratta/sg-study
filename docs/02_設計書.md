## 1. アーキテクチャ

### 1.1 全体構成

```
┌──────────── Mac（開発・コンテンツ生成）──────────────┐
│ IPA 公式 PDF ──► scripts/（文字抽出・OCR・パース）     │
│       ▼                                               │
│ content-src/（問題 JSON・教科書 Markdown。人手で修正）  │
│       ▼  npm run build:content（検証・HTML 化・一覧生成）│
│ public/content/（配信用 JSON。バージョン番号付き）      │
└──────────────────┬────────────────────────────────────┘
                   │ git push → 自動デプロイ
                   ▼
        静的ホスティング（Cloudflare Pages / GitHub Pages）
                   │ 初回アクセス時とコンテンツ更新時だけ通信
                   ▼
┌──────────── iPhone（Safari → ホーム画面アプリ）────────┐
│ public/（HTML・CSS・JS）◄── Cache Storage（Service Worker）│
│ 学習記録 ──► IndexedDB（端末内のみ、外部送信なし）        │
│ バックアップ JSON ──► 共有シート → 「ファイル」/ iCloud Drive │
└──────────────────────────────────────────────────────────┘
```

### 1.2 設計原則

- サーバーを持たない。アプリは静的ファイルだけで動き、学習記録は端末内にだけ置く。
- ランタイムはビルド不要（素の HTML / CSS / ES Modules）。生成が必要なのはコンテンツだけ。
- コンテンツは「原稿（content-src）」と「配信物（public/content）」を分け、配信物はスクリプトで生成する。
- 問題・教科書は「知識項目」単位でタグ付けし、現行シラバス（Ver.4.1）と新制度案（Ver.0.1）のどちらの分類でも表示できる。

### 1.3 gungi-online からの流用と差分

| gungi-online の要素 | 今回の扱い |
|---|---|
| `public/` 直下に HTML・CSS・JS を置くビルド不要構成 | 流用。ES Modules に分割する |
| 画面を `div` + `hidden` クラスで切り替える方式 | 流用。タブ 5 画面 + サブ画面（出題中、教科書ページ）をハッシュルーティングで切替 |
| `style.css` のモバイル対応（`@media (max-width: 600px)`、`touch-action: manipulation`、`prefers-reduced-motion`） | 流用。今回はモバイルファーストで書き直し、セーフエリアとダークモードを追加 |
| README の「ローカル起動」「デプロイ」「ディレクトリ構成」の書き方 | 流用 |
| `server.js`（Express）、`socket.io`、`server/auth.js`（合言葉ゲート）、`server/rooms.js` | 使わない。サーバーなし、認証なし |
| `render.yaml`（Render Web Service） | 使わない。静的ホスティングに変更 |
| `shared/`（サーバー・クライアント共用ロジック） | 考え方だけ流用。採点・集計・SRS を DOM 非依存の純粋関数（`public/js/core/`）にまとめ、Node のテストから直接呼べるようにする |

## 2. 技術スタック

| 層 | 採用 | 理由 |
|---|---|---|
| UI | HTML / CSS / JavaScript（ES2020 Modules）、フレームワークなし | ビルド不要。gungi-online と同じ運用感 |
| オフライン | Service Worker（自作、事前キャッシュ一覧はビルド時に生成）、Web App Manifest | iOS でホーム画面アプリ化とオフライン動作に必要 |
| 学習記録 | IndexedDB（自作の薄いラッパー `db.js`、約 150 行）。設定は localStorage | 回答履歴は数万件になり得るため localStorage では不足 |
| グラフ | インライン SVG を自作（ヒートマップ、棒、折れ線、リング） | ライブラリ不要、軽い、ダークモード対応が容易 |
| コンテンツ生成 | Node.js 20（`scripts/*.mjs`、`marked` を devDependency）、Python 3（`pypdf`、`pypdfium2`） | Markdown → HTML、PDF 抽出 |
| OCR（筆記時代） | macOS 標準の Vision フレームワーク（Swift スクリプトまたは pyobjc）。比較用に Tesseract（jpn） | 日本語精度が高く、クラウド不要 |
| テスト | `node --test`（core の純粋関数）、ビルド時の JSON 検証 | 依存を増やさない |
| ホスティング | Cloudflare Pages（推奨）または GitHub Pages | 無料、`git push` で自動デプロイ |

### 4.2 教科書（`textbook/<topicId>.json`）

- 単位は原則「小分類」。重点分野の A1 は分量が多いので「項目」単位に分割する（脅威、マルウェア、攻撃手法、暗号、認証、ISMS、リスク管理、インシデント管理、物理的対策、技術的対策、法規 など）。目安は 60〜80 ページ。
- 原稿は `content-src/textbook/<topicId>.md`。frontmatter に `title`、`topicIds`（対応する小分類／項目）、`newTopicIds`、`readingMinutes`、`updatedAt` を持つ。
- 本文の構成を固定する: **要点（3〜5 行）→ 解説 → 試験での問われ方・ひっかけ → 用語集 → 関連問題（自動付与）**。
- ビルド時に Markdown を HTML に変換し、用語集と関連問題 ID（同じ `tags.item` を持つ問題）を埋め込む。

```json
{
  "id": "A1-1-3",
  "title": "脅威の種類と攻撃者",
  "topicIds": ["A1-1-3"],
  "newTopicIds": ["N6-23"],
  "summary": ["脅威は「事故・災害・故障」などの偶発的なものと、「不正アクセス・なりすまし」などの意図的なものに分かれる", "…"],
  "html": "<h3>…</h3><p>…</p>",
  "glossary": [ { "term": "ソーシャルエンジニアリング", "desc": "人の心理的な隙を突いて情報を得る手口。…" } ],
  "relatedQuestionIds": ["2026r08-a-03", "sample2022-a-02"],
  "readingMinutes": 6,
  "updatedAt": "2026-11-05"
}
```

### 4.3 問題（`questions/<setId>.json`）

科目 A 形式（四肢択一）:

```json
{
  "id": "2026r08-a-01",
  "exam": "SG",
  "kind": "A",
  "source": {
    "year": "令和8年度", "session": "公開問題", "part": "科目A・B", "no": 1,
    "citation": "情報セキュリティマネジメント試験 令和8年度 公開問題 問1",
    "url": "https://www.ipa.go.jp/shiken/mondai-kaiotu/sg_fe/koukai/rcu1hd0000012qj6-att/2026r08_sg_qs.pdf",
    "modified": false, "modifiedNote": ""
  },
  "stem": "……はどれか。",
  "choices": [
    { "key": "ア", "text": "……" }, { "key": "イ", "text": "……" },
    { "key": "ウ", "text": "……" }, { "key": "エ", "text": "……" }
  ],
  "answer": ["ウ"],
  "figures": [ { "src": "figures/2026r08-a-10.webp", "alt": "サブネットの表", "position": "stem" } ],
  "tags": { "sub": "A1-4", "item": "A1-4-2", "newSub": "N6-25", "field": "T" },
  "explanation": { "html": "<p>……</p>", "author": "claude", "reviewed": false },
  "flags": { "outdated": false, "note": "" },
  "difficulty": 2
}
```

科目 B 形式（ケース + 設問）:

```json
{
  "id": "2026r08-b-13",
  "exam": "SG",
  "kind": "B",
  "source": { "year": "令和8年度", "session": "公開問題", "part": "科目A・B", "no": 13, "citation": "情報セキュリティマネジメント試験 令和8年度 公開問題 問13", "url": "…" },
  "case": {
    "html": "<p>A 社は，従業員 300 名の専門商社であり……</p><h4>〔来訪者管理〕</h4><p>……</p>",
    "sections": ["本文", "来訪者管理", "B ビルの物理的セキュリティにおける課題と B 社への依頼"]
  },
  "stem": "表 1 中の……に入れる字句の適切な組合せはどれか。",
  "choices": [ { "key": "ア", "text": "……" }, { "key": "イ", "text": "……" }, { "key": "ク", "text": "……" } ],
  "answer": ["エ"],
  "tags": { "skill": "B6", "sub": "A1-4", "newSub": "N6-25" },
  "explanation": { "html": "…", "author": "claude", "reviewed": false }
}
```

設計上の決め事:

- `answer` は配列。「2 つ選べ」形式に備える。
- 選択肢の順番はシャッフルしない。IPA の問題は「ア と イ の両方」のような選択肢を含むため、並べ替えると意味が壊れる。
- 図表を含む問題は `figures` にページ画像の切り出し（WebP）を添付する。初期は座標ファイル（`figures.yaml`）を手で書き、将来は自動検出に置き換える。
- 筆記時代の問題は `tags.field` に解答例の分野（T／S／M）をそのまま入れ、小分類タグは Claude の分類結果を本人が確認したうえで `reviewed: true` にする。
- 法改正などで現在と答えが変わる問題は `flags.outdated = true` と `note` を付け、出題時に注記を表示する（出題から外すかは設定で選べる）。
- 旧午後の大問（長文）は `kind: "B-legacy"` とし、設問ごとに分割して科目 B の読解練習に使う。分割は改変にあたるため `source.modified = true`、`modifiedNote = "大問を設問単位に分割"` を必ず付ける。

### 4.4 出典表記ルール

IPA の利用条件に合わせ、出題画面と解説画面の末尾に `source.citation` を常に表示する。書式は「情報セキュリティマネジメント試験 {年度}{期} {時間区分} 問{番号}」。例:

- 情報セキュリティマネジメント試験 令和元年度秋期 午前 問 1
- 情報セキュリティマネジメント試験 令和8年度 公開問題 問 13
- 情報セキュリティマネジメント試験 サンプル問題セット（2022 年 12 月公開）問 49

改変がある問題は「※ 原文の一部を変更しています: {modifiedNote}」を併記する。設定画面の「出典・ライセンス」に、IPA の利用条件と本アプリの扱い（個人の学習目的、解説は自作）を明記する。

### 4.5 コンテンツのバージョン管理（`index.json`）

```json
{
  "contentVersion": 12,
  "builtAt": "2026-11-05T09:00:00+09:00",
  "files": {
    "syllabus.json": { "hash": "a1b2…", "bytes": 48213 },
    "questions/2026r08.json": { "hash": "…", "bytes": 61002 },
    "textbook/A1-1-3.json": { "hash": "…", "bytes": 9120 }
  },
  "counts": { "questionsA": 120, "questionsB": 24, "topics": 42 }
}
```

アプリは起動時に `index.json` をネットワーク優先（3 秒でタイムアウト）で取りに行き、`contentVersion` が上がっていればバナーで更新を促す。更新を受け入れると Service Worker が差分ファイルを取得してからリロードする。

## 5. 学習記録のデータモデル（IndexedDB `sg-study`）

| ストア | キー | 内容 |
|---|---|---|
| `attempts` | `id`（自動採番）。索引: `qid`, `day`, `sessionId` | 1 回の回答。`{ qid, ts, day:"2026-11-05", mode:"drill"\|"review"\|"exam"\|"case", chosen:["ウ"], correct:true, elapsedMs, sessionId, examId }` |
| `questionState` | `qid` | 問題ごとの集計。`{ attempts, correct, wrong, streak, lastTs, lastCorrect, srs:{ step:0, dueTs:0, reps:0 }, bookmarked:false, note:"" }` |
| `topicState` | `topicId` | 教科書の状態。`{ status:"unread"\|"reading"\|"done", rating:0..3, lastTs, readCount }` |
| `sessions` | `id` | 演習セッション。`{ startTs, endTs, mode, filter:{sub,setId,…}, qids, answered, correct }` |
| `exams` | `id` | 模試。`{ startTs, endTs, status:"running"\|"done"\|"abandoned", qids, answers:{qid:["ア"]}, remainingMs, result:{ correctA, correctB, scaled, perSub } }` |
| `dailyStats` | `day` | 日次集計（派生。attempts から再計算可能）。`{ answered, correct, studyMs, topicsRead, sessions }` |
| `meta` | `key` | `schemaVersion`, `contentVersion`, `installedAt`, `lastBackupTs` |

設定（localStorage `sg-study.settings`）: `examDate`, `dailyGoal`（問題数、既定 10）, `theme`（system／light／dark）, `syllabusView`（"4.1"／"new"）, `fontScale`, `includeOutdated`, `strictExamTimer`。

書込みは `attempts` を正とし、`questionState` と `dailyStats` は同一トランザクションで更新する。整合性が崩れた場合は設定画面の「集計を再計算」で `attempts` から作り直せるようにする。

### 5.1 バックアップと復元

- 書き出し: 全ストアを 1 つの JSON（`{ schemaVersion, exportedAt, contentVersion, settings, stores:{…} }`）にまとめ、`navigator.share({ files })` で共有シートを開く（iOS 15 以降でファイル共有に対応）。「ファイルに保存」で iCloud Drive へ置ける。未対応環境では `a[download]` にフォールバック。
- 読み込み: `<input type="file" accept=".json">` → スキーマ検証 → **マージ**（`attempts` を `qid+ts` で重複排除して結合し、`questionState` と `dailyStats` を再計算）または **置換**（全消去して読込）を選択。
- バナー: 最終バックアップから 14 日経過、または直近バックアップ以降の回答が 200 件を超えたらホームに「バックアップしましょう」を出す。

## 7. 主要ロジック

### 7.1 出題選択（`core/select.js`）

1. フィルタ（種別 A／B、分野、問題セット、`outdated` の除外）で候補集合を作る。
2. 問題ごとに重みを付ける: 未出題 3.0、復習期限超過 2.0、最新回答が誤答 2.0、正解 3 連続以上 0.3、直近 24 時間以内に出題 0.1、それ以外 1.0。
3. 重み付きランダムで非復元抽出。同一セッション内で重複させない。
4. 弱点優先モードは、弱点分野（出題 5 問以上かつ正答率 60% 未満。該当がなければ正答率の低い順に 3 分野）の問題に候補を限定する。

### 7.2 間隔反復（`core/srs.js`）

- 階段方式（Leitner 風）。間隔の階段は `[1, 3, 7, 14, 30, 60]` 日。
- 正解したら 1 段上がり、`dueTs = now + interval`。誤答したら 0 段目に戻る。
- 「今日の復習」は `dueTs <= 今日の終わり` の問題を期限の古い順に最大 20 問。
- 模試中の回答は SRS を更新しない（本番形式の実力測定のため）。ドリル／復習／ケース演習は更新する。

### 7.3 進捗指標（`core/stats.js`）

| 指標 | 定義 |
|---|---|
| カバー率（分野） | 出題済み問題数 ÷ 分野の問題数 |
| 正答率（分野） | 分野の出題済み問題のうち、最新回答が正解だった割合 |
| 定着率（分野） | SRS の段が 2（7 日）以上の問題の割合 |
| 弱点 | 出題 5 問以上かつ正答率 60% 未満 |
| 連続学習日数 | その日に回答 1 問以上または教科書 1 ページ読了がある日の連続。日付はローカル時刻 |
| 目標達成率 | 今日の回答数 ÷ 1 日の目標 |
| 必要ペース | 未出題問題数 ÷ 試験日までの日数（「あと 1 日 14 問で全問 1 周」） |
| 合格目安スコア | Σ（分野ウェイト × 分野正答率）× 1000。ウェイトの既定は 科目 A 重点分野 0.55、科目 A 関連分野 0.25、科目 B 0.20（`content/scoring.json` で変更可）。本番は IRT 採点なので一致しない旨を画面に明記 |

### 7.4 模擬試験（`core/exam.js`）

- 構成: 科目 A 48 問 + 科目 B 12 問。科目 A は分野配分の既定（セキュリティ 28、法務 4、テクノロジ 4、マネジメント 6、ストラテジ 6）に従って抽出し、過去 30 日に出題した問題を避ける。科目 B は在庫が約 24 問しかないため、未出題を優先し、不足時は既出を使って画面に表示する。
- タイマー 120 分。0 になったら自動提出。中断時は `remainingMs` を保存して再開できる（厳格モードでは中断不可）。
- 結果: 正答数（A／B）、換算目安（1000 × (0.8 × A 正答率 + 0.2 × B 正答率)）、分野別内訳、全問の見直し（解説付き）。結果は `exams` に保存し、進捗画面で推移を表示する。

### 7.5 日次集計

- 回答のたびに `dailyStats[today]` を更新する。学習時間は「出題から回答まで」の合計で、1 問あたり 5 分を上限にして放置を除外する。
- 日付境界はローカル時刻の 0 時（端末のタイムゾーン）。

## 8. PWA と iOS 対応

### 8.1 マニフェストとメタタグ

- `manifest.webmanifest`: `name: "SG 学習"`, `short_name: "SG学習"`, `start_url: "./?src=pwa"`, `display: "standalone"`, `lang: "ja"`, `theme_color`, `background_color`, icons 192／512（maskable）。
- `index.html` の head: `viewport` に `viewport-fit=cover`、`apple-mobile-web-app-capable=yes`、`apple-mobile-web-app-status-bar-style=default`、`apple-touch-icon`（180 px）、`theme-color`（ライト／ダーク両方）。
- `navigator.standalone` が false（Safari で開いている）のときは、初回にだけ「共有 → ホーム画面に追加」の案内を表示する。

### 8.2 CSS

- 高さは `100dvh`、タブバーは `padding-bottom: env(safe-area-inset-bottom)`。
- `touch-action: manipulation`、`-webkit-tap-highlight-color: transparent`、`overscroll-behavior: none`（引っ張り更新の誤動作防止）、入力欄は 16 px 以上（フォーカス時の自動ズーム防止）。
- ダークモードは `prefers-color-scheme` と設定の両対応。色は CSS 変数で定義。
- `prefers-reduced-motion` でアニメーションを止める（gungi-online と同じ）。

### 8.3 Service Worker（`sw.js`）

- インストール時: `sw-manifest.json` の一覧（アプリ本体 + `content/` 全ファイル）を事前キャッシュ。キャッシュ名に `contentVersion` を含める。
- 取得戦略: アプリ本体と `content/` はキャッシュ優先。`content/index.json` だけネットワーク優先（3 秒でキャッシュにフォールバック）。
- 更新: 新しい SW は `waiting` で止め、アプリ側のバナーで「更新」を押したときに `skipWaiting` → `clients.claim` → リロード。古いキャッシュは `activate` で削除。
- 外部リンク（IPA の PDF）は SW を通さず `target="_blank"` で開く。

### 8.4 ストレージ

- 起動時に `navigator.storage.persist()` を要求する（ホーム画面アプリでは自動的に許可される見込み。結果を設定画面に表示）。
- Safari の 7 日ルールへの備えとして、5.1 のバックアップ導線を必ず用意する。

### 8.5 開発時の確認方法

- Mac: `npm run dev`（`npx serve public` 相当）で `http://localhost:8080`。localhost では Service Worker が動く。Safari の「レスポンシブ・デザイン・モード」で iPhone サイズを確認。
- iOS シミュレータ（Xcode）: Safari で同じ URL を開き、ホーム画面に追加してスタンドアロン動作とオフライン（ネットワークリンクコンディショナ）を確認。
- 実機: LAN の `http://` では Service Worker が動かないため、デプロイ先のプレビュー URL（Cloudflare Pages のブランチプレビュー）で確認する。

## 9. コンテンツ生成パイプライン

```
raw/*.pdf
  │ extract_pdf.py（文字抽出・layout モード／ページ画像化）
  │ ocr_pdf.swift（筆記時代のみ。Vision で日本語 OCR）
  ▼
work/<setId>.txt + pages/*.png
  │ parse_questions.py（問番号・選択肢・解答例の突合、図表の要否判定）
  ▼
content-src/questions/<setId>.json（reviewed: false）
  │ Claude Code のセッションで一括: 解説の下書き、小分類タグ、outdated 判定
  │ 本人が確認して reviewed: true（まとめて承認も可）
  ▼
build-content.mjs（検証 → HTML 化 → public/content/ → sw-manifest.json → index.json）
  ▼
git commit / push → 自動デプロイ → アプリに更新バナー
```

| 工程 | 内容 | 備考 |
|---|---|---|
| 取得 | `fetch-ipa.sh` が [04_公式ソース一覧.md](04_公式ソース一覧.md) の URL を `raw/` に保存 | `raw/` は git 管理外 |
| 抽出 | `pypdf` の layout モードで文字を取り、`pypdfium2` でページを PNG 化 | 2022 年以降の PDF はこれで十分 |
| OCR | 筆記時代（H28〜R1）の問題冊子は画像のみ。macOS Vision で OCR し、解答例 PDF（文字抽出可）と突合して問番号の欠落を検出 | まず 2 回分で精度を測り、誤認識の多いパターン（「，」「ー」「ウ／ウ」など）を補正辞書で直す |
| パース | 「問 N」で分割、選択肢「ア／イ／ウ／エ」（科目 B は〜ク）を検出、解答例と結合。図表参照（「図 1」「表 1」「次の表」）があれば `needsFigure` を立てる | 折り返しで問番号が崩れるケースがあるため、行頭の座標情報も使う |
| 図表 | `figures.yaml` に `{ qid, page, x, y, w, h }` を書いて `crop_figures.py` で WebP に切り出す | 初期は手作業。件数は 1 割程度の見込み |
| 解説・タグ | Claude Code のセッションで `content-src/questions/*.json` を読み、解説 HTML、`tags.sub/item`、`flags.outdated` を書き戻す | API キー不要。1 セット（約 15〜60 問）ずつ |
| 教科書 | シラバスの「項目・用語例」を骨組みに Markdown を執筆。重点分野から | 各ページに関連問題が自動で付く |
| ビルド | スキーマ検証（`answer` が `choices` に含まれる、A は選択肢 4 つ、タグがシラバスに存在、出典あり）→ HTML 化 → 配信物生成 | 検証に失敗したらビルドを止める |

## 10. テストと品質

- `tests/` で `core/` の純粋関数を `node --test` で検証する: 出題重み、SRS の遷移、日次集計と連続日数（日付境界）、合格目安、模試の分野配分、バックアップのマージ。
- ビルド時の JSON 検証を CI（GitHub Actions）でも実行し、壊れたコンテンツをデプロイしない。
- 手動確認のチェックリスト: ホーム画面追加、機内モードで全画面が開く、回答が保存される、バックアップ JSON が「ファイル」に保存できる、復元後に進捗が一致する、更新バナーが出る。

## 11. デプロイと運用

### 11.1 Cloudflare Pages（推奨）

1. GitHub に `sg-study` リポジトリを作る（非公開でよい）。
2. Cloudflare Pages で「Git に接続」→ ビルドコマンドなし、出力ディレクトリ `public`。
3. `public/_headers` でキャッシュ制御: `sw.js` と `content/index.json` は `Cache-Control: no-cache`、それ以外は長めに。
4. 発行される `https://sg-study.pages.dev` を iPhone の Safari で開き、ホーム画面に追加。

### 11.2 GitHub Pages（代替）

- GitHub Free では公開リポジトリが必要。`actions/upload-pages-artifact` で `public/` を配信する。
- URL は `https://lammratta.github.io/sg-study/` になるため、`start_url` と SW の scope を相対パスにしておく。

### 11.3 更新の流れ

コンテンツや機能を直す → `npm run build:content` → `npm test` → commit → push → 自動デプロイ → 次回起動時にバナー「新しいコンテンツ（v13）があります」→ 更新。学習記録は端末内にあるので更新で消えない。

## 12. セキュリティとプライバシー

- 個人データ（学習記録・メモ）は端末の IndexedDB と、本人が保存したバックアップファイルにしか存在しない。外部送信・解析ツール・Cookie なし。
- 配信物は IPA 公式問題（出典明記）と自作教材のみ。URL が知られても困る情報は含めない。
- 依存ライブラリはランタイムではゼロ、生成側も `marked`、`pypdf`、`pypdfium2` に限定する。

## 13. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 筆記時代 PDF の OCR 精度が低い | 400 問の取り込みが遅れる | 公開問題 + サンプル問題 120 問で MVP を成立させ、OCR は 2 回分で検証してから拡大。誤認識は本人確認時に修正 |
| 図表を含む問題の見た目 | 解きにくい | ページ画像の切り出しを添付。件数は少ないので手作業で対応 |
