- 作成日: 2026-10-26
- 対象: 自分専用の iPhone 学習アプリ（個人利用）
- 関連文書: [02_設計書.md](02_設計書.md) / [03_開発ロードマップ.md](03_開発ロードマップ.md) / [04_公式ソース一覧.md](04_公式ソース一覧.md)

## 1. 企画の概要

### 1.1 目的

IPA 情報セキュリティマネジメント試験（以下 SG）の合格に向けて、iPhone だけで「学ぶ → 解く → 振り返る」を毎日回せる自分専用の学習アプリをつくる。学習の積み上がりを見える化して、受験日までモチベーションを維持する。

### 1.2 利用者と利用シーン

- 利用者は本人のみ。アカウント、複数ユーザー、共有機能は不要。
- 通勤電車、昼休み、就寝前の 5〜20 分。片手・縦画面・オフライン（地下鉄）でも使える。

### 1.3 要件の整理（会話で確定した方針）

| 項目 | 方針 |
|---|---|
| 利用形態 | iPhone の中で自分だけが使う。オンライン対戦のような常時接続・サーバーは不要 |
| 配布 | Apple の審査（App Store）を通さない |
| 参考構成 | gungi-online（Vanilla JS・ビルド不要・Render）の作り方で流用できる部分は流用する |
| 欲しい機能 | 教科書的な学習コンテンツ／実際の過去問（公式問題）を手軽に解ける演習／学習履歴・進捗がわかる画面 |

## 2. 実現方式の比較と推奨

| 方式 | Apple 審査 | オフライン | 導入の手間 | 更新方法 | 備考 |
|---|---|---|---|---|---|
| **A. PWA**（静的サイトを Safari で開き「ホーム画面に追加」） | 不要 | ○（Service Worker でキャッシュ） | URL を開いて追加するだけ | `git push` で自動反映 | サーバー不要。学習記録は端末内に保存 |
| B. ネイティブ（Xcode + 無料 Apple ID で実機インストール） | 不要 | ○ | Mac に接続して Xcode から都度インストール | 署名が 7 日で切れるため再インストール | 継続利用には不向き |
| C. ネイティブ（Apple Developer Program 年額 99 USD、Ad Hoc / TestFlight 内部テスト） | 不要（内部テストは審査なし） | ○ | 証明書・プロビジョニングの管理 | Ad Hoc は年 1 回再署名、TestFlight は 90 日で期限 | 有料かつ手間 |
| D. App Store 配信 | 必要 | ○ | 審査対応 | 審査のたびに待ち | 要望に反する |

**推奨は A の PWA。** 理由は次のとおり。

- Apple 審査も Developer Program も不要で、初回に URL を開いてホーム画面に追加するだけで「アプリ」として使える。
- Service Worker でアプリ本体と問題データをキャッシュするので、2 回目以降はオフラインで動く。
- gungi-online の「ビルド不要の Vanilla JS」「public/ 配下に静的ファイル」の作り方をそのまま活かせる。Express と Socket.IO は不要になるので、サーバー側のコードは持たない。
- 学習記録は端末内の IndexedDB にだけ保存し、外部に送らない。

PWA の制約と対策:

| 制約 | 対策 |
|---|---|
| Safari は「7 日間使われないサイト」のスクリプト書込みストレージを削除することがある。ホーム画面に追加した Web アプリは実際の使用日でカウントされる（WebKit 公式ブログの見解）が、保証ではない | JSON のバックアップ／復元を必須機能にする。`navigator.storage.persist()` を起動時に要求する。2 週間バックアップがなければバナーで促す |
| プッシュ通知は iOS 16.4 以降のホーム画面 Web アプリで可能だが、通知サーバーが必要 | MVP では採用しない。学習リマインドは iOS 標準「リマインダー」で代替 |
| 初回だけ URL へのアクセスが必要（静的ホスティングが必要） | Cloudflare Pages か GitHub Pages の無料枠を使う |
| 配信 URL は公開状態になる | 載せるのは IPA 公式問題と自作教材だけ。学習記録は端末外に出ない |

## 3. 試験の基礎情報（2026-10-26 時点、IPA 公式サイト調べ）

### 3.1 現行制度

| 項目 | 内容 |
|---|---|
| 実施方式 | CBT（テストセンターの PC）で随時実施（通年） |
| 試験時間 | 120 分（科目 A・B 通し） |
| 出題数 | 60 問 = 科目 A 48 問（四肢択一・知識）+ 科目 B 12 問（多肢選択・ケーススタディ） |
| 採点 | IRT（項目応答理論）による評価点 |
| 合格基準 | 総合評価点 600 点以上（1,000 点満点） |
| 科目 A の範囲 | 重点分野: 情報セキュリティ全般・情報セキュリティ管理・情報セキュリティ対策・関連法規／関連分野: テクノロジ（ネットワーク、DB、システム構成要素）、マネジメント（監査、サービス、プロジェクト）、ストラテジ（経営、戦略、企画） |
| 科目 B の範囲 | 情報資産管理、リスクアセスメント、IT 利用時の安全確保、委託先管理、教育・訓練などを題材にしたケース |
| シラバス | Ver.4.1（2025-04-17 掲載。Ver.4.0 からの変更は「プロバイダ責任制限法」→「情報流通プラットフォーム対処法」）。試験要綱は Ver.5.6（2026-07-06） |
| 受験料 | 7,500 円（税込）。申込サイト CBT-Solutions で要確認 |

### 3.2 重要: 現行試験は 2026-12-27 で一旦休止、2027 年度春から新制度

- 試験システムのリプレースのため、**2026-12-28 以降は CBT を休止**（会場によっては 12/27 より前に休止）。2026-09-01 以降の新規申込では 12/27 までの開催日しか選べない。再開時期は未定で「2027 年 1 月以降の実施は 2026 年秋頃に案内」とされている。バウチャー購入受付も 2026-07-31 に一時停止。
- 現行の試験制度は 2026 年度の実施をもって終了。**2027 年度春頃から新制度**へ移行する。SG は名称そのまま継続し、科目 A 48 問 + 科目 B 12 問・120 分も同じ。科目 A は出題範囲の「体系（分類の表記）」が変わるが、問う知識・技能の範囲は変わらないとされている。科目 B は出題範囲の一部を変更。新制度のシラバス案 Ver.0.1 が 2026-09-30 に公開済み。SG の新制度サンプル問題は未公開（2026-10 時点）。

受験計画への影響（本人の判断事項）:

| 選択肢 | 受験時期 | 学習期間 | 備考 |
|---|---|---|---|
| (A) 現行制度で受験 | 2026-12-27 まで | 約 2 か月 | 公開問題・サンプル問題と形式が完全一致。年末は席が埋まりやすいので早めの申込が必要 |
| (B) 新制度で受験 | 2027 年 4 月以降（詳細未発表） | 5 か月以上 | 問われる知識は同じ。科目 B の変更点はサンプル問題の公開後に反映 |

アプリへの反映: 問題と教科書は「知識項目」単位でタグ付けし、現行シラバス（Ver.4.1）と新シラバス案（Ver.0.1）の両方の分類にマッピングできるようにする。どちらを選んでも作り直しは不要。

### 3.3 新制度シラバス案（Ver.0.1）の科目 A 体系（参考）

- 重点分野: 大分類 6 セキュリティ（中分類 23 情報セキュリティの脅威／24 情報セキュリティマネジメント／25 情報セキュリティ対策）、大分類 7 倫理・コンプライアンス（29 プライバシー関連法規／30 セキュリティ関連法規）
- その他の分野: サービスマネジメント、データ分析・データ利活用、AI 利活用、経営・組織論、ガバナンス・監査、クラウド、ネットワーク、セキュリティ実装技術・評価、情報倫理・AI 倫理、ビジネス関連法規

現行と比べて「データ・AI の利活用」「クラウド」「AI 倫理」「ランサムウェア対策」が明示的に加わっている。教科書ではこの差分を「新制度で追加」ラベル付きで補う。

## 4. 利用できる公式問題ソースと権利関係

### 4.1 ソース一覧

| ソース | 時期 | 問題数（概算） | 形式 | PDF の文字抽出 |
|---|---|---|---|---|
| 筆記試験 午前（四肢択一） | H28 春〜R1 秋の 8 回 | 50 問 × 8 = 400 問 | 現行の科目 A と同形式 | **不可（画像のみ）→ OCR が必要** |
| 筆記試験 午後（長文・大問） | 同 8 回 | 3 大問 × 8 = 24 大問 | 旧形式（長文に複数設問） | 不可 → OCR |
| サンプル問題セット（2022-12 掲載） | 現行形式 | 60 問（科目 A 48 + 科目 B 12） | 現行形式 | 可 |
| 科目 B サンプル問題（2022-04 掲載） | 現行形式 | 数問 | 現行形式 | 可 |
| 公開問題 令和 5〜8 年度 | 毎年 7 月公開 | 各年約 15 問（科目 A 12 + 科目 B 3）= 約 60 問 | 現行形式（本番の一部） | 可 |
| 新制度サンプル問題（SG） | 未公開 | - | 新形式 | 公開され次第取り込む |

合計の目安: 科目 A 形式 約 520 問、科目 B 形式 約 24 問。旧午後の 24 大問は科目 B 対策の読解教材として活用する。令和 2〜4 年度の問題は IPA が非公開のため入手できない。

### 4.2 利用条件（IPA「試験に関するよくある質問」より要約）

- IPA が公表した過去問題は、法令に特別の定めがある場合を除き、許諾も使用料も不要。ダウンロード利用も可。
- 著作権は放棄されていない。資格制度の意義に反しない範囲（教育目的など）で問題集・テキストに使用できる。
- 出典を明記する（年度・期・試験区分・時間区分・問番号。例: 「情報セキュリティマネジメント試験 令和元年度秋期 午前 問 1」）。
- 一部を改変した場合はその旨を明記する。
- 電子データは PDF のみ提供。PDF セキュリティの解除方法等は提供されない。

アプリでの扱い: 各問題に出典を常時表示し、改変（表記ゆれの修正、図の差し替えなど）があれば注記する。他社・他サイトの解説やデータは使わず、解説は自作する。

## 5. 機能要件

### 5.1 全体像

画面下部の 5 タブで構成する: **ホーム／教科書／演習／進捗／設定**。

### 5.2 機能一覧

優先度: ◎ MVP で必須、○ 第 2 段階、△ 将来

| 演習 | 科目 A ドリル | ◎ | 1 問ずつ出題 → 即時正誤 → 解説 → 出典。モード: ランダム／分野別／年度別／弱点優先／未出題優先 |
| 演習 | 科目 B ケース演習 | ○ | ケース文を読みやすく分割表示、設問は画面下部に固定、解答群はア〜ク |
| 演習 | 復習（間隔反復） | ○ | 間違えた問題を間隔反復で再出題。期限が来た分を「今日の復習」に表示 |

| 演習 | 模擬試験 | ○ | 48 + 12 問、120 分タイマー、中断・再開、結果レビュー、1,000 点換算の目安スコア |

| 共通 | オフライン動作 | ◎ | 初回表示後はネットワーク不要 |
| 共通 | ダークモード | ○ | OS 設定に追随 |

### 5.3 「手軽に回答」の UX 原則

- 起動 1 秒以内。前回の続きから再開できる。
- 選択肢は大きなタップ領域（高さ 56px 以上）で、親指が届く画面下半分に置く。
- 回答 → 結果 → 次へ を 1 タップずつ。次の問題へはスワイプでも進める。
- 1 セッションは 10 問を標準（通勤 1 駅分）。終了時に「今日の積み上げ」を表示する。

## 6. 非機能要件

| 項目 | 要件 |
|---|---|
| 動作環境 | iPhone の Safari（iOS 17 以降を想定）。ホーム画面追加でスタンドアロン表示。Mac の Safari／Chrome でも動作（開発・確認用） |
| オフライン | 初回ロード後は全機能をオフラインで利用可 |
| 性能 | 起動 1 秒以内、画面遷移 100 ms 以内（問題データは JSON を事前キャッシュ） |
| データ | 学習記録は端末内（IndexedDB）のみ。外部送信なし、解析ツールなし |
| 保守 | ビルド不要の Vanilla JS。コンテンツは JSON／Markdown で管理し、スクリプトで生成 |
| 配信 | 静的ホスティング（Cloudflare Pages または GitHub Pages）の無料枠 |

## 7. コンテンツ方針

- 問題は IPA 公式のみ。出典を各問題に表示する。解説は Claude が下書きし、本人が確認・修正する。解説の誤りは学習の害になるので、公開問題・サンプル問題を優先し、筆記時代の問題は分野タグと解説を段階的に充実させる。
- 教科書はシラバス Ver.4.1 の体系と用語例を骨組みにして各項目を執筆する。「試験で問われやすい観点」「ひっかけポイント」「関連する過去問」を必ず付ける。法改正（個人情報保護法、情報流通プラットフォーム対処法など）は最新内容に合わせ、古い問題には「現在は〜」の注記を付ける。
- 分野タグは現行（Ver.4.1）と新制度案（Ver.0.1）の 2 系統を持つ。筆記時代の解答例には分野（T／S／M）しか付かないため、小分類タグは Claude で機械分類してから本人が確認する。

## 8. スコープ外（やらないこと）

- マルチユーザー、ログイン、サーバーサイド、端末間同期（バックアップ JSON を iCloud Drive に置くことで代替）
- プッシュ通知（MVP 時点）
- App Store 配信
- 他の試験区分。ただしデータに「試験区分」を持たせ、将来 FE や AP へ広げられる構造にする

## 9. 成功の定義

- アプリ: 2 週間以内に MVP を iPhone に導入し、以降は毎日使える状態にする。
- 学習: 科目 A 形式の全問を 1 周、弱点分野の正答率 80% 以上、模試換算 600 点以上を 3 回連続で達成してから受験する。
