## 1. スケジュールの考え方

- 受験時期が **(A) 2026-12-27 まで** なら、11 月上旬に MVP を iPhone へ投入し、残り約 7 週間を演習に使う。教科書は重点分野だけ先に作る。
- 受験時期が **(B) 2027 年春以降** なら、MVP の後に教科書と科目 B を厚くし、新制度のサンプル問題が出た時点で取り込む。
- どちらでも Phase 0〜1 は同じ。Phase 2 以降の順番と深さだけ変える。

## 2. フェーズ

### Phase 0: 基盤とコンテンツの PoC（目安 3 日）

- リポジトリ作成、ディレクトリ構成、ローカル起動、Cloudflare Pages（または GitHub Pages）への接続
- 公式 PDF の取得スクリプト（URL 一覧は [04_公式ソース一覧.md](04_公式ソース一覧.md)）
- 文字抽出できる PDF（サンプル問題セット 60 問、公開問題 R5〜R8 約 60 問）のパースと解答例との突合。JSON スキーマで検証
- 解説の下書き生成（Claude）、出典表記の自動付与、小分類タグ付け
- 判断ポイント M0: 約 120 問が JSON 化できていること。OCR が必要な筆記時代の問題は Phase 2 に回す

### Phase 1: MVP（目安 1 週間）

- PWA の骨格: manifest、Service Worker、5 タブ UI、iOS 向けメタタグ、セーフエリア対応
- 科目 A ドリル（ランダム／分野別／未出題優先）、即時正誤、解説、出典表示
- 学習記録（IndexedDB）: 回答履歴、問題ごとの状態、日次集計
- ホーム: 今日の学習量、連続日数、試験日カウントダウン、クイックスタート
- 進捗: ヒートマップ、分野別の正答率とカバー率
- 設定: 試験日、1 日の目標、バックアップ／復元、データ削除
- iPhone へ導入し、機内モードでオフライン動作を確認
- 判断ポイント M1: iPhone で 1 日 10 問を無理なく回せること

### Phase 2: 定着（目安 1〜2 週間）

- 間隔反復による復習、「今日の復習」キュー、ブックマークとメモ
- 教科書（重点分野を先行）、用語検索、理解度セルフ評価
- 合格目安ゲージ、弱点優先モード、ダークモード
- 筆記時代 午前 400 問の OCR 取り込み。まず 2 回分（100 問）で精度を検証し、十分なら全 8 回へ
- 判断ポイント M2: 弱点分野が進捗画面で一目でわかること

### Phase 3: 本番対策（目安 1〜2 週間）

- 科目 B ケース演習（サンプル 12 問 + 公開問題 約 12 問）
- 模擬試験（120 分タイマー、中断・再開、結果レビュー、スコア推移）
- 教科書（その他の分野）、実績バッジ
- 判断ポイント M3: 模試換算 600 点以上が安定すること

### Phase 4: 新制度対応と拡張（随時）

- 新制度の SG サンプル問題・確定版シラバスの取り込み、新体系タグへの切替
- 旧午後大問の読解教材化
- 他の試験区分（FE など）への拡張

## 3. 作業量の目安

| フェーズ | 実装 | コンテンツ作成 | 合計の目安 |
|---|---|---|---|
| Phase 0 | 0.5 日 | 2 日（パース・解説 120 問） | 3 日 |
| Phase 1 | 4 日 | 1 日（解説の確認） | 1 週間 |
| Phase 2 | 3 日 | 4〜6 日（教科書 重点分野 約 40 ページ、OCR 400 問） | 1〜2 週間 |
| Phase 3 | 3 日 | 3〜4 日（科目 B 解説、教科書 その他の分野） | 1〜2 週間 |

実装は Claude Code が行い、コンテンツ（解説・教科書）も Claude が下書きする前提。本人の作業は、方針の決定、解説の確認、iPhone での動作確認が中心。
