## 要点

- 暗号化はファイル・ディスク・通信の3つの層で行い、端末の紛失・盗難時の情報漏えいを防ぐ。抜き取られたストレージに効くのは**ストレージ側の保護**（ディスク暗号化、HDDパスワード）。暗号化消去は鍵を破棄してデータを読めなくする廃棄法
- ランサムウェア対策の中心は**バックアップ**。3-2-1ルール（3つの複製、2種類の媒体、1つは遠隔地）とWORM・オフライン保管で、バックアップ自体の暗号化を防ぐ。レプリケーションやRAIDでは壊れる前の時点に戻せない（新制度で追加）
- **DLP**は機密情報の持出しを内容で検知・遮断する。MDMはスマートフォンなどを一元管理し、紛失時はリモートワイプする
- 無線LANは**WPA3**（なければWPA2）を使う。SSIDの隠蔽やMACアドレスフィルタリングは補助にすぎず、盗聴や偽装を防げない
- メールのなりすまし対策は**送信ドメイン認証**のSPF（送信元IP）、DKIM（電子署名）、DMARC（失敗時の扱いを指定）。内容の暗号化・署名はS/MIME
- クラウドは**責任共有モデル**で、利用者側の設定ミスやアクセスキー漏えいが事故の主因（新制度で追加）

## 解説

### データの暗号化と安全な廃棄

端末の紛失・盗難や媒体の持出しに備え、データは保存時と通信時に暗号化する。

| 方式 | 対象 | 特徴 |
| --- | --- | --- |
| **ファイル暗号化** | 特定のファイルやフォルダ | 持出しや共有時の保護に使う |
| **ディスク暗号化**（BitLockerなど） | ドライブ全体 | OSを起動せずにディスクを抜いて読み取る手口にも有効 |
| 通信の暗号化 | ネットワーク上のデータ | TLSやVPNで行う |

暗号化した情報は、鍵を安全に破棄すれば、データ本体が残っていても復元できなくなる。これを**暗号化消去**（CE）といい、クラウドやSSDのように、データの物理的な上書きが難しい環境での廃棄方法として位置づけられる。

### ストレージの抜取りへの備え

PCの内蔵ストレージを抜き取られ、攻撃者が用意したPCにつながれると、元のPCで設定した守りの多くは働かない。

| 対策 | 抜き取られたときの効果 |
| --- | --- |
| OSのログインパスワード、ファイルのアクセス権 | 効かない。別のPCや別のOSから読み出せば、元のOSの制御を経ずに取り出せる |
| BIOSパスワード（PCの起動時に動く基本プログラムに設定するもの） | 効かない。PC本体の起動や設定変更を制限するだけで、ストレージ自体は守らない |
| **HDDパスワード** | 効く。ストレージ自身にロックがかかり、別のPCにつないでも正しいパスワードなしでは読み書きできない |
| ディスク暗号化 | 効く。鍵がなければ中身を読めない |

**抜取りに有効なのは、ストレージ側で守る仕組み**である。

### バックアップとランサムウェア対策

**バックアップ**は、障害や誤操作だけでなく、ランサムウェアからの復旧の要である。近年のランサムウェアは、ネットワーク上のバックアップも探して暗号化する。そのため、次の対策を組み合わせる（新制度で追加）。

- **3-2-1ルール**: データを3つ持ち、2種類の媒体に保存し、1つは遠隔地に置く
- **オフライン保管**: ネットワークから切り離して保管する
- **WORM**: 一度書いたら変更・削除できない機能をもつストレージを使う
- **リストア試験**: 復元できるかを定期的に確かめる

毎回すべてを取るフルバックアップと、変更分だけを取る差分バックアップや増分バックアップを組み合わせることも多い。バックアップの設計では、次の3つを決める。

| 決めること | 何が決まるか |
| --- | --- |
| 取得の頻度 | 失うデータの量。障害が起きると、最後に取得した後の更新が失われる |
| 世代数（保存期間） | どこまで過去に戻れるか。不具合や感染の発覚が遅れても、正常だった時点に戻せる |
| 媒体と保存場所 | 媒体の故障や拠点の被災に耐えられるか。1本の媒体だけに頼らない |

**失うデータを減らすには取得の頻度を上げる**。媒体を速いものに替えたり、遠隔地に保管したりしても、取得の間隔が同じなら失う量は変わらない。

**レプリケーション**（データの変更をほぼ即時に別の装置へ複製する仕組み）や**RAID**（RAID 1やRAID 5のように、複数のディスクにデータを冗長に記録する技術）は、装置やディスクの故障には強い。しかし、誤操作やアプリケーションの不具合による論理的な破損や、ランサムウェアによる暗号化も、そのまま複製される。**壊れる前の時点に戻すには、世代を分けて保存したバックアップが必要**である。

### 情報漏えい対策の技術

**DLP**（Data Loss Prevention）は、文書の内容やキーワード、指紋情報から機密情報を識別し、メール送信、Webアップロード、USBへのコピーなどの持出しを検知・遮断する。

データそのものを守る手法には、次のものがある。

- **データマスキング**: 本番データの一部を伏せ字や架空の値に置き換える
- **匿名化**: 個人が特定できないよう加工する。項目削除、レコード削除、セル削除、極端な値を丸めるトップ（ボトム）コーディング、同じ属性の人が最低k人いるようにする**k-匿名化**などがある
- **電子透かし**: 画像や文書に見えない識別情報を埋め込み、流出元の特定や改ざん検知に使う

### デジタルフォレンジックスと証拠保全

**デジタルフォレンジックス**は、インシデントの原因究明や法的な手続に備えて、PCやサーバ、ネットワーク機器に残る電子データを証拠として収集・保全し、調査・分析する技術と手続である。

証拠の価値を保つため、原本のディスクやログは改変せずに保全し、ディスクは複製（イメージ）を作って複製の側を解析する。**原本と複製のハッシュ値を記録し、一致することで両者が同一で改変されていないことを示す**。ハッシュ値は固定長の要約なので、ハッシュ値から元のデータを復元することはできない。

### 端末と外部記憶媒体の管理

スマートフォンやタブレットなど携帯端末は、**MDM**（Mobile Device Management）で一元管理する。画面ロックや暗号化の強制、アプリの制限、紛失時の**リモートワイプ**（遠隔消去）や位置特定を行う。

私物端末を業務に使う**BYOD**では、MDMや業務領域の分離を条件に許可し、ルールを規程で定める。ネットワークカメラなどのIoT機器は、初期パスワードの変更とファームウェア更新が基本である。

USBメモリなどの**外部記憶媒体**は、原則禁止または会社支給の暗号化媒体に限定し、端末側でUSBポートの使用を制御する。リスクは、データが流れる向きで2つに分けて考える。

| 向き | 主なリスク |
| --- | --- |
| 媒体からPCへ（読込み・コピー） | マルウェア付きのファイルや、許可していないソフトウェアの持込みによるPCの感染 |
| PCから媒体へ（書込み） | 情報の持出し、感染したPCから媒体への感染の拡大 |

**どちらの向きを技術的に禁止したかで、低減できるリスクが決まる**。書込みだけを禁止しても、媒体からの感染は防げない。

### 無線LANの設定

無線LANは電波が届く範囲で誰でも受信できるため、**暗号化方式が最重要**である。

- **WEP**: 解読済みで使用禁止
- **WPA3**: 現在の推奨。SAEという鍵交換により、パスワードが短くてもオフラインでの総当たりに強い
- **WPA2**: WPA3に対応していない機器では、AESを使って利用する

SSIDを隠す（ステルス）設定や**MACアドレスフィルタリング**は、補助的な効果しかない。SSIDもMACアドレスも、電波を傍受すれば分かり、偽装できるからである。来客用には、業務用と別のSSIDとネットワークを用意する。

### 電子メールの対策

なりすましメール対策の中心は**送信ドメイン認証**である。

| 方式 | 仕組み |
| --- | --- |
| **SPF** | 送信ドメインのDNSに正規の送信サーバのIPアドレスを公開し、受信側が送信元のIPアドレスと照合する |
| **DKIM** | 送信サーバがメールに電子署名を付け、受信側がDNSで公開された公開鍵で検証する |
| **DMARC** | SPF・DKIMの検証に失敗したメールを「何もしない・隔離・拒否」のどれにするかを送信側がDNSで宣言し、結果のレポートを受け取る |

メール本文の暗号化と署名には、**S/MIME**やPGPを使う。迷惑メールは、単語の出現確率で学習する**ベイジアンフィルタリング**などで判定する。**誤送信対策**には、宛先の再確認画面、送信の一時保留、添付ファイルの自動暗号化、BCC強制などがある。

### クラウドとWebの対策

クラウドでは、基盤の安全は事業者、データやアカウント・設定の安全は利用者が担う**責任共有モデル**が前提である。実際の事故の多くは、ストレージの公開設定ミスや、プログラム中に書かれた**アクセスキー**の漏えいが原因である。

対策は、設定の定期点検、アクセスキーの権限最小化と定期的な更新、管理者の多要素認証である。SaaSの利用状況を可視化・制御する**CASB**も使われる（新制度で追加）。

Webの出口対策としては、**URLフィルタリング**（Webフィルタリング）で、業務に無関係な分類のサイトや既知の悪性サイトへのアクセスを遮断する。**コンテンツフィルタリング**は、通信内容に含まれる不適切な情報を遮断する。

## 試験での問われ方

- 3-2-1ルールの意味と、ネットワークにつないだままのバックアップはランサムウェア対策として不十分という判断。**失うデータの量は取得の頻度**で決まり、レプリケーションやRAIDでは論理的な破損から戻せない
- MACアドレスフィルタリングやSSIDステルスを「十分な無線LAN対策」とする選択肢は誤り。正解は「**WPA3/WPA2による暗号化**」
- SPFは「送信元IPアドレス」、DKIMは「電子署名」、DMARCは「**失敗時の扱いの宣言**」。S/MIMEは「本文の暗号化と署名」であり、なりすまし送信元の判定とは目的が異なる
- ディスク暗号化の効果は「端末紛失時の情報漏えい防止」で、マルウェア感染防止ではない。抜き取ったストレージに効くのは**ストレージ側の保護**で、OSのログインやBIOSのパスワードは効かない
- 責任共有モデルでは「**データの管理やアクセス設定は利用者の責任**」。「クラウドなら全て事業者が守る」は誤り
- k-匿名化やデータマスキングは「個人を特定できなくする加工」、DLPは「**持出しの検知・遮断**」、フォレンジックスのハッシュ値は「原本と複製の同一性の証明」と、機能で区別する

## 用語集

- **ファイル暗号化・ディスク暗号化**: ファイル暗号化は特定のファイルやフォルダを、ディスク暗号化はドライブ全体を暗号化する。ディスク暗号化はディスクを抜き取って読む手口にも有効。
- **暗号化消去（CE）**: 暗号鍵を破棄してデータを復元不能にする廃棄方法。クラウドやSSDで有効。
- **HDDパスワード**: ストレージ自身に設定するパスワード。正しく入力するまで読み書きできず、別のPCにつないでもロックが続く。
- **バックアップ**: データの複製を別の場所に保存すること。障害・誤操作・ランサムウェアからの復旧手段。
- **3-2-1ルール**: 3つの複製を2種類の媒体に保存し、1つは遠隔地に置くバックアップの原則。
- **WORM**: 一度書き込んだら変更・削除できないストレージの機能。バックアップの改ざん・暗号化を防ぐ。
- **ランサムウェア対策**: オフラインやWORMのバックアップ、復元試験、EDRなどを組み合わせた対策。
- **レプリケーション**: データの変更をほぼ即時に別の装置へ複製する仕組み。装置の故障に強いが、誤操作や論理的な破損も複製されるため、バックアップの代わりにはならない。
- **DLP**: 機密情報の内容を識別し、メールやUSBなどによる持出しを検知・遮断する仕組み。
- **データマスキング**: データの一部を伏せ字や架空の値に置き換えて機密性を保つ加工。
- **匿名化**: 個人を特定できないように加工すること。項目削除、トップコーディング、k-匿名化など。
- **k-匿名化**: 同じ属性の組合せをもつ人が最低k人になるよう加工し、個人の特定を困難にする手法。
- **秘匿化**: 情報を暗号化や伏せ字などで第三者に分からない形にすること。
- **電子透かし**: 画像や文書に見えない識別情報を埋め込み、流出元の特定や改ざん検知に使う技術。
- **デジタルフォレンジックス**: 事故の証拠となる電子データを改変せず収集・保全し、分析する技術と手続。原本と複製の同一性はハッシュ値で示す。
- **MDM**: スマートフォンなどを一元管理し、設定強制やリモートワイプを行う仕組み。
- **BYOD**: 私物端末の業務利用。MDMなどを条件に許可し、規程で管理する。
- **リモートワイプ**: 紛失した端末のデータを遠隔から消去する機能。
- **外部記憶媒体の管理**: USBメモリなどの使用を禁止・限定し、暗号化媒体や持出し記録で管理すること。読込みと書込みの向きごとに制御する。
- **WPA3・WPA2**: WPA3は現在推奨される無線LANの暗号化方式で、SAEによりパスワードの総当たりに強い。WPA2はその前の方式でAESを使えば利用可能。WEPは使用禁止。
- **MACアドレスフィルタリング**: 登録した機器だけ接続を許す機能。MACアドレスは偽装できるため補助的対策。
- **SPF**: 送信ドメインの正規サーバのIPアドレスをDNSに公開し、受信側が照合する送信ドメイン認証。
- **DKIM**: 送信サーバが電子署名を付け、受信側がDNSの公開鍵で検証する送信ドメイン認証。
- **DMARC**: SPF・DKIM失敗時の扱い（なし・隔離・拒否）を送信側が宣言し、レポートを受け取る仕組み。
- **S/MIME**: 電子証明書を使ってメール本文を暗号化・電子署名する規格。
- **ベイジアンフィルタリング**: 単語の出現確率を学習して迷惑メールを判定する手法。
- **誤送信対策**: 宛先再確認、送信保留、添付ファイルの自動暗号化などで誤送信による漏えいを防ぐ対策。
- **責任共有モデル**: クラウドの基盤は事業者、データや設定、アカウントは利用者が守るという責任分担。
- **アクセスキー管理**: クラウドAPIの認証キーを最小権限で発行し、ソースコードに書かず、定期的に更新する管理。
- **URLフィルタリング（Webフィルタリング）**: 分類や拒否リストに基づき不適切・危険なサイトへのアクセスを遮断する仕組み。
