## 要点

- マルウェア対策ソフトは**パターンマッチング**（定義ファイル）が基本で、定義ファイルはできるだけ短い間隔で自動更新する。未知のマルウェアにはビヘイビア法（振る舞い検知）やヒューリスティック法、サンドボックスで対応する
- **EDR**は「侵入される前提」で端末の挙動を記録・監視し、侵入後の検知と対応（隔離・調査）を行う。従来型対策ソフトの置き換えではなく補完
- **脆弱性管理**はOSやソフトの更新とセキュリティパッチの適用が中心。IT資産管理ツールやSBOMで、使っているソフトウェアを把握する
- ファイアウォールは通信の可否を判断、IDSは侵入を検知して通知、IPSは検知して遮断、WAFはWebアプリケーション層の攻撃を防ぐ。**役割の違い**が頻出
- 公開サーバは**DMZ**に置き、内部ネットワークと分ける。多層防御は一つの対策に頼らず、入口・内部・出口の対策を重ねる設計
- **ゼロトラスト**は「社内だから信頼する」をやめ、全てのアクセスを毎回検証する考え方。SASEはネットワークとセキュリティ機能をクラウドで統合して提供する

## 解説

### マルウェア対策ソフトと検出手法

**マルウェア対策ソフト**は、端末やサーバに常駐してファイルや通信を検査し、マルウェアを検出・駆除する。主な検出手法は次のとおり。

| 手法 | 仕組み | 特徴 |
| --- | --- | --- |
| **パターンマッチング法** | 既知マルウェアの特徴（シグネチャ）を収めた定義ファイルと照合する | 未知のものは検出できない |
| **ヒューリスティック法** | コードの構造や命令から「マルウェアらしさ」を推定する | 未知の亜種にもある程度対応 |
| **ビヘイビア法**（振る舞い検知） | 実行時の挙動（ファイルの大量暗号化、外部通信など）で判定する | 未知マルウェアに有効 |
| **サンドボックス** | 隔離された仮想環境で疑わしいファイルを実行させ、挙動を観察する | 本番環境を危険にさらさずに確かめられる |
| コンペア法・チェックサム法 | 安全な原本や、そのハッシュ値と比較して改変を見つける | 改変の有無は分かるが、マルウェアの種類は分からない |

**検査対象のプログラムを実行する必要があるのは、ビヘイビア法とサンドボックス**である。パターンマッチング法やコンペア法・チェックサム法は、ファイルを実行せずに中身を調べる。

**マルウェア定義ファイル**は、ベンダーが新しいマルウェアに対応するたびに公開する。端末側の更新が1日1回などでは、公開から更新までの間に届いたマルウェアを見逃すおそれがある。そのため、**できるだけ短い間隔で自動更新**し、更新が止まっている端末を管理者が把握できるようにする。

検出では、見逃しである**フォールスネガティブ**と、誤検知である**フォールスポジティブ**がトレードオフになる。

許可するものだけを列挙する**許可リスト**（パスリスト）方式は、未知のものも止められるが運用負荷が高い。悪性のものを列挙する**拒否リスト**（ブロックリスト）方式は、手軽だが新種に弱い。

### マルウェアの解析

見つかった検体（疑わしいファイル）の正体や機能を調べるマルウェア解析は、検体を実行するかどうかで2つに分かれる。

| 解析 | 方法の例 |
| --- | --- |
| **静的解析** | 実行せずに調べる。ハッシュ値を既知のマルウェアのリストと照合する、含まれる文字列を調べる、逆コンパイルして得たコードを読む |
| **動的解析** | サンドボックスなどの隔離環境で実際に実行し、ファイルやレジストリの変更、外部との通信などの動作を観測する |

**逆コンパイル**は、実行形式のプログラムを、人が読めるソースコードに近い形に戻すことである。ファイルの拡張子と中身の形式（先頭のヘッダ情報）を照らし合わせ、文書などに見せかけた実行ファイル（拡張子の偽装）を見つける検査も、実行を伴わない検査である。

### EDRと侵入後の対応

標的型攻撃や未知のマルウェアは、入口対策だけでは防ぎきれない。**EDR**（Endpoint Detection and Response）は、端末上のプロセス起動、通信、ファイル操作を継続的に記録し、不審な挙動を検知したら端末の隔離、原因調査、復旧を支援する製品である。

目的は「**侵入を前提に早く見つけて被害を最小化する**」ことで、マルウェア対策ソフトと併用する。近年は、AIで異常を検知する「AI for Security」と、AIシステム自体を守る「Security for AI」の両面が重視されている（新制度で追加）。

### 感染が疑われるときの初動

不審な添付ファイルを開いてしまったなど、感染が疑われるときは、**被害の拡大を防ぐことを優先**する。

- 社内ネットワークやVPNにつながず、ネットワークから切り離して、上司や窓口に報告する
- 不審なファイルを開き直したり、他の人や共有フォルダに渡したりしない
- 定義ファイルを最新にしたマルウェア対策ソフトでフルスキャンする。感染を広げないよう、社内ネットワークにつながない状態で行う
- IDやパスワードが盗まれた可能性があれば、パスワードを変更する。身に覚えのない多要素認証の承認要求は、IDとパスワードが知られているサインである
- 感染が疑われる端末をそのままバックアップしても、マルウェアごと保存するだけで、被害の拡大防止にはならない

### 脆弱性管理とパッチ適用

多くの侵入は既知の脆弱性を突く。**脆弱性管理**は、使用ソフトウェアを把握し、脆弱性情報（JVNなど）を収集し、深刻度を評価して、**セキュリティパッチ**の適用やOSアップデートを計画的に行う活動である。

全ての端末を最新に保つには、**IT資産管理ツール**で各端末のソフトウェアとバージョンを自動で集め、パッチを一斉に配布・適用する方法がある。会社が把握していないソフトウェアは更新が漏れやすいため、**許可していないソフトウェアのインストールを禁止し、見つけたら削除する**ことも対策になる。EDRやSIEMは攻撃を見つける仕組みで、ソフトウェアを最新にする仕組みではない。

ソフトウェアの部品構成を一覧にした**SBOM**（Software Bill of Materials）があれば、部品に脆弱性が見つかったときの影響範囲をすぐ特定できる。

サーバでは、使わないサービスを止めることも基本である。**ポートスキャナ**で自組織のサーバの各ポートに接続を試み、稼働しているサービスを一覧にして、不要なサービスが動いていないことを確かめる。攻撃者も侵入前の偵察で同じ調査をするため、先に確認して止めておく。

### ネットワーク境界の防御機器

| 機器 | 役割 |
| --- | --- |
| **ファイアウォール** | IPアドレスやポート番号で通信の可否を決める（パケットフィルタリング）。通信の状態を追跡し、内部からの要求への応答だけ通すのがステートフルインスペクション |
| **IDS** | 攻撃の兆候を検知して管理者に通知する。遮断はしない |
| **IPS** | 検知に加えて攻撃通信を自動で遮断する。通信経路上に置く |
| **WAF** | HTTPの内容を検査し、SQLインジェクションやXSSなどWebアプリケーション層の攻撃を防ぐ |
| **UTM** | FW、IDS/IPS、マルウェア対策、URLフィルタリングなどを1台に統合した機器 |
| **プロキシ** | 内部端末の代わりにWebへアクセスする中継サーバ。URLフィルタリングやログ取得を行う |

IDSやIPSは、ベンダーが提供する**シグネチャ**（既知の攻撃パターン）と通信を照合するなどの方法で攻撃を見つける。

ファイアウォールは、主にポート番号でサービスを区別する。代表的なものは次のとおり。

| ポート番号 | 用途 |
| --- | --- |
| 80 | HTTP（Webの閲覧） |
| 443 | HTTPS（暗号化したWebの閲覧） |
| 53 | DNS（名前解決や、DNSサーバ間で情報を複製するゾーン転送） |

多くの組織は、Webの閲覧に使う80番と443番の通信を、内部から外部へ向けては許可している。**マルウェアはこれを悪用し、C&Cサーバ（指令サーバ）との通信に80番や443番を使って、通常のWeb通信に紛れ込む**。そのため、プロキシのログ監視やURLフィルタリングなどの出口対策で不審な通信を見つける。

**DMZ**（非武装地帯）は、Webサーバやメールサーバなどの公開サーバを置く、インターネットと内部ネットワークの中間の区画である。**公開サーバが乗っ取られても、内部へ直接到達させない**ことが目的である。

このほかの仕組みは次のとおり。

- **検疫ネットワーク**: 接続しようとする端末を一旦隔離区画につなぎ、パッチや定義ファイルが最新かを検査してから本番ネットワークへ入れる。持込みPCからの感染拡大を防ぐ
- **ハニーポット**: わざと脆弱に見せた囮で攻撃者を引き付け、手口を観察する
- **SSL/TLSアクセラレーター**: 暗号処理を専用機器で代行する装置

### 多層防御とインターネット分離

**多層防御**は、次の対策を重ね、一つが破られても次で止める設計である。

- 入口対策: FW、メールフィルタ
- 内部対策: EDR、アクセス制御、ログ監視
- 出口対策: プロキシでの不審通信遮断

**インターネット分離**は、業務ネットワークとインターネット閲覧環境を分け、Web経由のマルウェアが業務網に入らないようにする。**Webアイソレーション**は、ブラウザを隔離環境で動かし、端末には画面描画だけを届ける方式で、使い勝手を保ちつつ分離を実現する。

実現方法の一つが**VDI**（仮想デスクトップ基盤）である。DMZなどに置いたサーバ上の仮想デスクトップのブラウザでWebを閲覧し、利用者のPCには画面だけを転送する。**Webから受け取ったファイルは仮想デスクトップ側にとどまり、内部ネットワークのPCには直接届かない**。

ただし、仮想デスクトップ自体が感染する可能性は残る。ブラウザに感染したマルウェアが送信内容を書き換えるMITB攻撃や、内部のPC同士の感染拡大は、VDIだけでは防げない。

### ゼロトラストとSASE

従来の**境界防御**は「社内ネットワークは安全」という前提に立つ。しかし、クラウド利用やテレワークで境界が曖昧になり、侵入後の横展開にも弱い。

**ゼロトラスト**は、**社内外を問わず全てのアクセスを信頼せず**、利用者の認証、端末の健全性などを毎回検証して最小権限で許可する考え方である（NIST SP 800-207が代表的な整理）。名前が似た次の用語と混同しないようにする。

- **ゼロデイ**: 修正プログラムが提供される前の脆弱性や、それを突く攻撃
- **ゼロ知識証明**: 秘密の情報そのものを明かさずに、それを知っていることを相手に証明する方法

**SASE**（Secure Access Service Edge）は、SD-WANなどのネットワーク機能と、クラウド型プロキシ（SWG）、CASB、ZTNAなどのセキュリティ機能を、クラウドサービスとして統合提供する枠組みである。場所を問わず同じポリシーを適用できる。クラウド前提のこれらの考え方は新制度で重視される（新制度で追加）。

## 試験での問われ方

- IDSとIPSの違い（検知して通知か、**遮断までするか**）、ファイアウォールとWAFの違い（ポート・アドレスか、HTTPの内容か）が最頻出
- 「定義ファイルを更新していれば未知のマルウェアも検出できる」は誤りで、未知への対策は振る舞い検知、ヒューリスティック、サンドボックス、EDR。**実行して判定するのはビヘイビア法**（動的解析）で、パターンマッチング法やコンペア法は実行しない。フォールスネガティブ（見逃し）とフォールスポジティブ（誤検知）の取り違えにも注意
- DMZは「**公開サーバを内部ネットワークから分離する**」区画で、「社内の全サーバを置く場所」は誤り。検疫ネットワークは「接続前に端末の状態を検査する」、ハニーポットは「囮で攻撃を観察する」と機能で区別する
- ゼロトラストは「**社内ネットワークでも信頼しない**」考え方で、「VPNで社内に入れば全て許可」は誤り。ゼロデイ、ゼロ知識証明との混同に注意
- 感染が疑われるときは「**切り離して報告**」「最新の定義ファイルで検査」「漏れた可能性のあるパスワードの変更」。添付ファイルを開き直す、VPNで社内につなぐ、は誤り
- マルウェアの通信は**許可されやすい80番・443番**に紛れるため、出口対策が要る。VDIによるインターネット分離の効果は「Webからのファイルが内部PCに届かない」こと

## 用語集

- **マルウェア対策ソフト**: マルウェアを検出・駆除するソフト。定義ファイルの更新と常駐監視が基本。
- **マルウェア定義ファイル**: 既知マルウェアの特徴（シグネチャ）を収めたデータ。できるだけ短い間隔で自動更新する。
- **パターンマッチング法**: 定義ファイルと照合して検出する手法。既知のものに強く、未知のものは検出できない。
- **ヒューリスティック法**: コードの特徴からマルウェアらしさを推定する手法。未知の亜種にある程度対応。
- **ビヘイビア法（振る舞い検知）**: 実行時の挙動で判定する手法。未知マルウェアの検出に有効。
- **サンドボックス**: 隔離された環境で疑わしいファイルを実行し挙動を観察する仕組み。
- **静的解析・動的解析**: マルウェアの検体を実行せずにハッシュ値やコードを調べるのが静的解析、サンドボックスなどで実行して動作を観測するのが動的解析。
- **フォールスネガティブ・フォールスポジティブ**: フォールスネガティブは悪性のものを見逃す検知漏れ、フォールスポジティブは正常なものを悪性と判定する誤検知。
- **許可リスト（パスリスト）・拒否リスト（ブロックリスト）**: 許可リストは許可する対象だけを列挙してそれ以外を拒否し、拒否リストは拒否する対象を列挙してそれ以外を許可する。拒否リストは新種に弱い。
- **EDR**: 端末の挙動を記録・監視し、侵入後の検知・隔離・調査を支援する製品。侵入前提の対策。
- **脆弱性管理**: 脆弱性情報の収集、深刻度評価、パッチ適用やOSアップデートを計画的に行うこと。
- **セキュリティパッチ**: 脆弱性を修正するプログラム。速やかな適用が基本。
- **SBOM**: ソフトウェアを構成する部品の一覧。脆弱性の影響範囲の特定に使う。
- **ファイアウォール**: IPアドレスやポート番号で通信の可否を決める機器・機能。
- **パケットフィルタリング**: パケットのヘッダ情報（アドレス、ポート）に基づく通過・遮断の制御。
- **ステートフルインスペクション**: 通信の状態を追跡し、内部からの要求に対する応答だけを通す方式。
- **DMZ（非武装地帯）**: 公開サーバを置くための、インターネットと内部ネットワークの中間区画。
- **IDS（侵入検知システム）**: 攻撃の兆候を検知して通知するシステム。遮断はしない。
- **IPS（侵入防止システム）**: 攻撃を検知し自動で遮断するシステム。通信経路上に設置。
- **WAF**: Webアプリケーションへの攻撃（SQLインジェクション、XSSなど）をHTTPの内容で検知・防御する。
- **UTM（統合脅威管理）**: 複数のセキュリティ機能を1台にまとめた機器。
- **プロキシ**: 内部端末の代わりに外部へアクセスする中継サーバ。URLフィルタリングやログ取得を行う。
- **検疫ネットワーク**: 接続しようとする端末を隔離区画で検査し、安全を確認してから本番網に入れる仕組み。
- **ハニーポット**: 攻撃者を誘い込んで手口を観察する囮のシステム。
- **多層防御**: 入口・内部・出口など複数の層に対策を重ね、一つが破られても次で止める設計。
- **インターネット分離**: 業務ネットワークとインターネット閲覧環境を分けてWeb経由の感染を防ぐこと。
- **Webアイソレーション**: ブラウザを隔離環境で実行し、端末には画面情報だけを届ける方式。
- **VDI**: サーバ上の仮想デスクトップを使い、端末には画面だけを転送する仕組み。Web閲覧に使うと、受け取ったファイルが端末に届かない。
- **ゼロトラスト**: 社内外を問わず全てのアクセスを信頼せず、毎回検証して最小権限で許可する考え方。
- **SASE**: ネットワーク機能とセキュリティ機能をクラウドで統合して提供する枠組み。
