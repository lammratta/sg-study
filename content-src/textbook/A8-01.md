## 要点

- **システム監査**は、独立した監査人が情報システムの利活用に係るリスクへの管理状況を検証・評価し、保証や助言を行う活動
- 手順は、監査計画→予備調査→本調査→評価・結論→監査報告→フォローアップ。監査人は改善を「実施」せず、改善状況を「**確認**」する
- 監査人には**独立性**（外観上・精神上）と客観性、正当な注意と秘密の保持が求められる。被監査部門と利害関係があってはならず、被監査部門の業務も行わない
- 監査証拠は十分かつ適切でなければならず、入手した証拠と評価の過程は**監査調書**に記録する
- 情報セキュリティ管理基準は、原則すべて実施する**マネジメント基準**と、リスクに応じて選ぶ管理策基準の2つで構成される
- 内部統制は4つの目的と6つの基本的要素で整理し、整備・運用の最終責任は**経営者**が負う。職務分掌が代表的な統制活動で、共謀や経営者による無視は内部統制の限界

## 解説

### システム監査の目的と基準

**システム監査**は、監査対象から独立した監査人が、情報システムの利活用に係るリスクに対するコントロール（管理策）が適切に整備・運用されているかを検証・評価し、保証を与えたり助言を行ったりする活動である。

監査で使う経済産業省の基準は、監査人がどう監査するかを示す**行為規範**と、組織がどう管理すべきかを示す**判断尺度**の組になっている。システム監査基準とシステム管理基準は、いずれも令和5年（2023年）に改訂されている。

| 監査の種類 | 行為規範 | 判断尺度 |
| --- | --- | --- |
| システム監査 | システム監査基準 | システム管理基準 |
| 情報セキュリティ監査 | 情報セキュリティ監査基準 | 情報セキュリティ管理基準 |

**情報セキュリティ管理基準**は、ISMSの規格であるJIS Q 27001（要求事項）とJIS Q 27002（管理策）に整合するように作られている。過去の試験で問われた平成28年改正版は、両規格の2014年版に合わせて改正されたものである。構成は次の2つの基準である。

- **マネジメント基準**: ISMSを確立し、運用し、点検し、改善するために組織が実施すべき事項。**原則としてすべて実施する**
- **管理策基準**: リスク対応のために選ぶ管理策の選択肢。リスクアセスメントの結果に応じて選び、**基準にない管理策を追加してもよい**

監査の目的や対象によって、次のような区分もある。

- **保証型監査**: 管理策が適切であることを監査人が言明する
- **助言型監査**: 改善すべき点を提言する
- **コンプライアンス監査**: 法令や行動指針、倫理、透明性の観点から業務が適切に行われているかを検証し、権利侵害行為や労働環境の問題点を指摘する

### 監査人の倫理と体制整備

監査が信頼されるためには、監査人が被監査部門から独立していなければならない。独立性には次の2つがある。

| 種類 | 意味 |
| --- | --- |
| **外観上の独立性** | 第三者から見て、被監査部門との間に利害関係や所属関係がないこと |
| **精神上の独立性** | 公正不偏の態度を保ち、客観的に判断すること |

**自分が設計したシステムを監査する、被監査部門の所属者が監査を担当する、といった状況は独立性を損なう**。監査人は、専門家としての正当な注意をもって業務にあたり、必要な能力を維持し、知り得た情報の秘密を保持しなければならない。

システム監査の体制を整備し、監査人の倫理を定めるのは組織の責任である。具体的には、監査の目的・権限・責任を規程で明確にし、必要な能力をもつ監査人を確保し、監査の品質を保つ仕組みを整える。これらは監査を始める前の**体制整備**であり、個々の監査の手順とは区別する。

### システム監査の手順

1. **監査計画**: 年度ごとの基本計画と、監査ごとの個別計画を立て、目的・対象範囲・時期・体制を決めて文書化する
2. **予備調査**: 文書の閲覧やヒアリングで対象の概要とリスクを把握し、本調査の重点を決める
3. **本調査**: 監査手続を実施して監査証拠を入手する。インタビュー、ドキュメントレビュー、現地調査、ウォークスルー（処理の流れを追跡）、チェックリスト、CAAT（コンピュータ支援監査技法）などの監査技法を使う
4. **評価・結論**: 入手した証拠を評価し、監査の結論を導く
5. **監査報告**: 監査報告書に指摘事項と改善提案をまとめ、監査の依頼者（経営者など）に報告する
6. **フォローアップ**: 被監査部門が行う改善の実施状況を監査人が確認する

**監査証拠**は、監査の結論を裏付けるのに十分な量で、かつ信頼できる適切なものでなければならない。監査の過程で入手した証拠、実施した手続、判断の根拠を記録したものが**監査調書**で、結論の正当性を後から検証できるように保存する。

システムが監査しやすいように作られていることを**可監査性**といい、処理の履歴を追跡できる記録（監査証跡）が残ることが条件になる。

例題1: 「監査人が、監査報告書に記載した改善提案に基づき、被監査部門に代わって改善策を実施した」は適切か。

答えは不適切である。改善の実施責任は被監査部門にあり、監査人が実施すると自分の作業を自分で監査することになり独立性を損なう。監査人の役割は、フォローアップで改善状況を確認することである。

### 監査人の行為と指摘事項

監査人の仕事は、管理の状況を**確かめて評価すること**であり、管理そのものを行うことではない。

| 監査人が行うこと | 監査人が行わないこと |
| --- | --- |
| 規程、台帳、ログなどの閲覧 | 規程や方針の制定 |
| 担当者への質問（ヒアリング） | 台帳や記録の作成・保管 |
| 現場の観察、記録と実物の突合 | 運用手続の実施 |
| 指摘事項と改善提案の報告、改善状況の確認 | 改善策の実施 |

表の「行わないこと」は**被監査部門の業務**であり、監査人が行うと自分の仕事を自分で監査することになって独立性を損なう。

**指摘事項**は、評価の結果、コントロールが不十分でリスクが残っていると判断した事項で、改善提案とともに監査報告書に記載する。手順が整備・周知されている、規程どおりに運用されている、といった状況は指摘事項にならない。

監査対象ごとの主な着眼点の例を示す。

| 監査対象 | 主な着眼点 |
| --- | --- |
| システムテスト | テストケースが要件を網羅している。テスト計画を利用部門と開発部門の責任者が承認している。本番環境から切り離した環境で、利用部門と開発部門が共同で実施している |
| アクセス制御 | 規程に基づいて必要最小限の権限を与え、異動・退職時に見直している。特権IDの利用を記録し点検している |
| インシデント管理 | 対応手順が整備・周知されている。影響の大きさや緊急度に応じて報告先と報告期限（エスカレーションの経路）を決めている。対応の記録を残している |

### 内部統制の目的と基本的要素

**内部統制**は、組織の業務が適正に行われるように経営者が整備し、組織の全員が運用する仕組みである。金融商品取引法は上場企業に財務報告に係る内部統制の整備と評価（内部統制報告書）を求め、会社法も内部統制システムの構築を求める。

日本の基準（金融庁の基準。米国のCOSOフレームワークを基にしたもの）では、内部統制の目的を、業務の有効性及び効率性、報告の信頼性、法令等の遵守、資産の保全の**4つ**とする。目的を達成するための**6つの基本的要素**は次のとおりである。

| 基本的要素 | 内容 | 例 |
| --- | --- | --- |
| 統制環境 | 組織の気風を決め、他の要素の基礎となる | 経営者の誠実性と姿勢、経営方針・経営戦略、組織構造 |
| リスクの評価と対応 | 目的の達成を妨げるリスクを識別・分析・評価し、対応を選ぶ | 脅威と脆弱性の分析、リスク対応策の決定 |
| 統制活動 | 経営者の命令・指示が確実に実行されるための方針と手続。業務プロセスに組み込む | 職務分掌、承認、照合、処理結果の検証 |
| 情報と伝達 | 必要な情報を識別・処理し、組織の内外に正しく伝える | 方針の周知、現場から経営者への報告経路 |
| モニタリング | 内部統制が有効に機能しているかを、日常的に、または独立した立場から継続的に評価する | 日常的な点検、CSA、内部監査 |
| ITへの対応 | 組織の内外のITに適切に対応する | IT環境への対応、ITの利用及び統制 |

統制環境は、経営者の姿勢や組織風土など他の要素の基礎である。統制活動の代表例が**職務分掌**で、1人に権限が集中しないように、申請と承認、入力と確認、開発と運用などを別の人に分ける。実施ルールの設定とチェック体制の確立もここに含まれる。

**業務の流れに組み込まれた承認・照合・検証は統制活動、独立した立場で行う内部監査はモニタリング**に当たる。モニタリングには、各部門が自ら統制の有効性を評価する**CSA**（統制自己評価）も含まれる。

### 内部統制の責任と役割

内部統制に関わる立場と役割は次のとおりである。

| 立場 | 役割 |
| --- | --- |
| 経営者 | 内部統制の整備・運用に最終的な責任を負う。上場企業では、財務報告に係る内部統制の有効性を自ら評価し、内部統制報告書を提出する |
| 取締役会 | 内部統制の整備・運用の基本方針を決め、経営者による整備・運用を監督する |
| 監査役 | 取締役の職務の執行を監査する立場から、内部統制の整備・運用の状況を独立して監視・検証する |
| 内部監査部門 | モニタリングの一環として、内部統制の整備・運用の状況を検討・評価し、改善を促す |
| 従業員 | 自分の業務に組み込まれた統制活動を実施する |

株主は、株主総会で取締役や監査役を選ぶ立場であり、内部統制を整備・運用する当事者ではない。**最終的な責任を負うのは経営者**である。

### ITへの対応と内部統制の限界

**ITへの対応**は、組織を取り巻くIT環境を把握して対応する「IT環境への対応」と、業務でITを利用し、そのITを統制する「ITの利用及び統制」からなる。ITに係る統制は次の2つに分かれる。

| 区分 | 内容 | 例 |
| --- | --- | --- |
| ITに係る全般統制 | 個々の業務処理統制が有効に働く基盤を保証する統制 | アクセス管理、変更管理、開発・保守の手続、運用管理、外部委託の管理 |
| ITに係る業務処理統制 | 個々の業務アプリケーションに組み込まれた統制 | 入力チェック、計算の正確性の確認、例外処理の承認 |

**全般統制が弱ければ、業務処理統制がいくら優れていても信頼できない**。

内部統制には限界があり、次のような場合には有効に機能しないことがある。

- 判断の誤りや不注意
- 複数の担当者による共謀
- 経営者による内部統制の無視・無効化
- 当初想定していなかった環境の変化や非定型の取引
- 費用と便益の比較から、すべてのリスクに統制を設けられないこと

**ITガバナンス**は、経営者がITの利活用を方向付け、評価し、監督する仕組みで、内部統制やシステム監査はその一部として位置付けられる。

## 試験での問われ方

- 監査人の**独立性を損なう例**（自分が開発したシステムを監査する、被監査部門の部員が監査する）を選ばせる
- 監査人の行為は**閲覧・質問・観察などによる証拠の入手と評価**。規程の制定、台帳の作成、運用や改善策の実施は誤りで、フォローアップは改善状況の確認
- 監査証拠の条件（十分かつ適切）、監査調書の目的（結論の根拠の記録）、**指摘事項はリスクが残る不備**であることと、テストやインシデント管理の着眼点が問われる
- 情報セキュリティ管理基準は**マネジメント基準と管理策基準の2つ**で構成され、JIS Q 27001・27002と整合する。マネジメント基準は原則すべて実施し、管理策は選択・追加できる
- 6つの基本的要素と例の対応（承認・照合・検証は**統制活動**、内部監査はモニタリング、経営方針は統制環境）、ITに係る全般統制と業務処理統制の例の区別が頻出
- 整備・運用の**最終責任は経営者**。職務分掌は「開発者が本番環境を操作できる」などへの正答で、内部統制の限界（共謀、経営者による無視）は「不正を完全に防げる」という誤りを見抜く材料になる

## 用語集

- **システム監査**: 独立した監査人が、情報システムの利活用に係るリスクへの管理策を検証・評価し、保証や助言を行う活動。
- **システム監査基準**: 監査人の行為規範を定めた経済産業省の基準。令和5年改訂。
- **システム管理基準**: 監査の判断尺度として、情報システムの管理のあるべき姿を示した基準。
- **情報セキュリティ監査基準・情報セキュリティ管理基準**: 情報セキュリティ監査における行為規範と判断尺度。
- **マネジメント基準・管理策基準**: 情報セキュリティ管理基準を構成する2つの基準。原則すべて実施する事項と、リスクに応じて選択・追加する管理策の選択肢。
- **保証型監査・助言型監査**: 管理策が適切であることを監査人が言明する監査と、改善すべき点を提言する監査。
- **監査人の倫理**: 誠実性、独立性、客観性、正当な注意、秘密保持など監査人が守るべき規範。
- **監査の独立性と客観性**: 被監査部門と利害関係をもたず（外観上）、公正不偏の態度で判断する（精神上）こと。
- **正当な注意と秘密の保持**: 専門家として相当の注意を払って監査し、知り得た情報を漏らさないこと。
- **監査計画**: 年度の基本計画と監査ごとの個別計画。目的・対象・時期・体制を定める。
- **予備調査・本調査**: 対象の概要とリスクを把握する事前調査と、監査手続で証拠を入手する本番の調査。
- **監査証拠**: 監査の結論を裏付ける資料や事実。十分かつ適切でなければならない。
- **監査調書**: 実施した監査手続、入手した証拠、判断の根拠を記録した文書。
- **指摘事項**: 監査の結果、コントロールが不十分でリスクが残っていると判断し、監査報告書に記載する事項。
- **監査報告書**: 指摘事項と改善提案をまとめ、監査の依頼者に報告する文書。
- **フォローアップ**: 監査報告後、被監査部門の改善の実施状況を監査人が確認すること。
- **可監査性**: 処理の履歴（監査証跡）が追跡でき、監査が実施しやすいシステムの性質。
- **コンプライアンス監査**: 法令、行動指針、倫理に沿って業務が行われているかを検証する監査。
- **内部統制**: 業務の適正を確保するために経営者が整備し、組織全員が運用する仕組み。
- **内部統制の基本的要素**: 統制環境、リスクの評価と対応、統制活動、情報と伝達、モニタリング、ITへの対応の6つ。
- **統制活動**: 経営者の指示が確実に実行されるよう、業務プロセスに組み込まれた方針と手続。職務分掌、承認、照合、検証など。
- **職務分掌**: 権限と責任を分け、申請と承認などを別の人が担当するようにして不正や誤りを防ぐこと。
- **実施ルールの設定・チェック体制の確立**: 業務の手順を明文化し、相互に確認する体制を作る統制活動。
- **モニタリング**: 内部統制が有効に機能しているかを継続的に評価する活動。
- **監査役**: 取締役の職務の執行を監査する会社の機関。内部統制の整備・運用の状況も独立した立場で監視・検証する。
- **ITに係る全般統制**: 業務処理統制が有効に機能する基盤となる統制。アクセス管理、変更管理、運用管理など。
- **ITに係る業務処理統制**: 個々の業務システムに組み込まれた統制。入力チェック、例外処理の承認など。
- **内部統制の限界**: 判断の誤り、共謀、経営者による無視、想定外の取引には内部統制が対応できないこと。
- **CSA（統制自己評価）**: 業務部門が自らの統制の有効性を評価し改善する手法。
- **ITガバナンス**: 経営者がITの利活用を方向付け、評価し、監督する仕組み。
