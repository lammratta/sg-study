## 要点

- プロジェクトは「独自の成果物を、定められた期間で生み出す有期の活動」。定常業務との違いは**有期性と独自性**
- プロジェクト憲章で正式に立ち上げ、**WBS**でスコープを作業に分解し、スコープ・スケジュール・コストのベースラインを基準に管理する
- 日程計画はPERT（アローダイアグラム）で作り、最も時間のかかる経路が**クリティカルパス**。この経路上の作業が遅れると全体が遅れる
- **EVM**はPV（計画価値）・EV（出来高）・AC（実コスト）を比べる。SV＝EV－PV、CV＝EV－AC、負なら遅れ・超過
- リスク対応は**回避・転嫁（移転）・軽減・受容**。品質管理ではパレート図や管理図などQC七つ道具を使う

## 解説

### プロジェクトとプロジェクトマネジメント

**プロジェクト**は、独自の製品やサービスを生み出すために行う有期の活動である。始まりと終わりがある点で、同じ業務を繰り返す定常業務と異なる。

**プロジェクトマネジメント**は、要求を満たすために知識・技能・手法を適用する活動である。立上げ・計画・実行・管理・終結という**プロジェクトライフサイクル**に沿って進める。

組織がプロジェクトを適切に方向付け、監督する仕組みを**プロジェクトガバナンス**という。日々の自己管理としては、変更の管理、問題の発見と報告、対策立案、文書化が求められる。

JIS Q 21500やPMBOK（第6版）では、管理の対象を次の10の対象群（知識エリア）に整理している。

| 対象群 | 主な内容 |
| --- | --- |
| 統合 | プロジェクト憲章、ベースライン、終結と教訓 |
| ステークホルダ | 関係者の特定と関わり方のマネジメント |
| スコープ | 範囲の定義、WBS、活動の定義 |
| 資源 | 人員・設備の見積り、チームのマネジメント |
| 時間 | 活動の順序付け、期間の見積り、スケジュール作成 |
| コスト | 予算、コストベースライン、EVM |
| リスク | リスクの特定・評価・対応・管理 |
| 品質 | 品質基準、検査 |
| 調達 | 外部からの購入、供給者の選定、契約 |
| コミュニケーション | 情報の配布方法 |

### 統合・ステークホルダ・スコープ

統合では、まず**プロジェクト憲章**を作成してプロジェクトを正式に認可し、目的・概略スコープ・プロジェクトマネージャの権限を定める。計画段階で承認されたスコープ・スケジュール・コストを**ベースライン**とし、以後の変更はベースラインとの差として管理する。終結時には成果物を引き渡し、**得た教訓**（うまくいったこと、失敗したこと）を収集して次のプロジェクトに生かす。

**ステークホルダ**は、プロジェクトの影響を受ける、または影響を与える個人や組織である。発注者・利用部門・経営層・協力会社などを早期に特定し、関心と影響力に応じて関わり方をマネジメントする。

**スコープ**は「何を作り、何をしないか」の範囲である。成果物と作業を階層的に分解し、管理できる大きさまで細かくしたものが**WBS**（作業分解構成図）で、最下位の要素（**ワークパッケージ**）が見積り、担当の割当て、進捗管理の単位になる。

WBSから活動（アクティビティ）を定義し、活動リストにまとめる。スコープの管理では、承認なしに範囲が膨らむことを防ぐ。**WBSは作業を分解して範囲を明確にするもので、作業の順序や日程は表さない**。

### 資源・時間（スケジュール）

資源では、必要な人員・設備を見積もり、プロジェクトチームをマネジメントする。時間では、活動の順序付け、活動期間の見積り、スケジュール作成を行う。

作業の順序関係と所要日数を矢線で表した図をアローダイアグラム（PERT図）といい、これを使って日程計画を立てる手法を**PERT**という。開始から終了までの各経路の所要日数を足し、最も長い経路を**クリティカルパス**という。クリティカルパス上の作業には余裕（フロート）がなく、1日遅れれば全体が1日遅れる。

例題1: 作業A（3日）の後にBとCが並行して始まり、B（4日）とC（2日）の両方が終わってからD（2日）を行う。経路はA→B→D＝3＋4＋2＝9日、A→C→D＝3＋2＋2＝7日である。

クリティカルパスはA→B→Dで、全体は9日になる。作業Cは2日遅れても全体に影響しない（余裕2日）。短縮したければクリティカルパス上のA・B・Dを短縮しなければならず、Cを短縮しても意味がない。

日程の表し方として、アローダイアグラムとガントチャートを使い分ける。

| 図 | 表すもの | 向いている用途 |
| --- | --- | --- |
| ガントチャート | 作業ごとの期間を横棒で表す | 各作業の開始・終了の時期と、現時点の進捗の確認。作業間の依存関係は表しにくい |
| アローダイアグラム（PERT図） | 作業の順序関係と所要日数を矢線で表す | クリティカルパスを求め、重点管理する作業を見つける |

期間を短縮する方法には、資源を追加して作業期間を縮める**クラッシング**（費用が増える）と、順に行う予定の作業を並行して進める**ファストトラッキング**（手戻りのリスクが増える）がある。日程と費用のトレードオフを分析し、費用の増加を抑えて期間を短縮する手法をCPM（クリティカルパス法）という。

**日程計画の技法はPERTとガントチャートである**。次の手法は予測や最適化のための手法で、日程計画の技法ではない。

- **回帰分析**: 変数間の関係を式で表し、予測に使う統計手法
- **時系列分析**: 時間とともに変わるデータの傾向や周期から、将来を予測する手法
- **線形計画法**: 制約条件の下で、利益が最大（費用が最小）になる資源の配分を求める手法

### コスト（EVM）

コストでは、見積りに基づく**コストベースライン**を基準に実績を管理する。進捗とコストを同時に見る手法が**EVM**（アーンドバリューマネジメント）で、次の3つの値を使う。

- **PV**（計画価値）: 現時点までに完了する予定だった作業の予算
- **EV**（出来高、アーンドバリュー）: 現時点までに実際に完了した作業の予算換算額
- **AC**（実コスト）: 現時点までに実際に使った費用

| 指標 | 式 | 悪い状態 |
| --- | --- | --- |
| SV（スケジュール差異） | EV－PV | 負（遅れ） |
| CV（コスト差異） | EV－AC | 負（予算超過） |
| SPI（スケジュール効率指数） | EV÷PV | 1未満 |
| CPI（コスト効率指数） | EV÷AC | 1未満 |

どの指標もEVを基準にし、**PVと比べれば進捗、ACと比べればコスト**が分かる。完成時総予算BACに対し、現在の効率が続くとした完成時総コストの見積りは、EAC＝BAC÷CPIで求める。

例題2: BAC1,000万円のプロジェクトで、ある時点のPVが500万円、EVが400万円、ACが450万円とする。SV＝400－500＝－100万円（遅れ）、CV＝400－450＝－50万円（超過）である。CPI＝400÷450≒0.89なので、EAC＝1,000÷0.89≒1,125万円となる。

### リスク・品質・調達・コミュニケーション

リスクには、プロジェクト全体に関わる**全体リスク**と、個々の事象である**個別リスク**がある。リスクマネジメントは、特定→評価（発生確率と影響度）→対応→管理（監視）の順で進め、**リスク登録簿**に記録する。

脅威への対応戦略は次の4つである。

- **回避**: 原因を取り除く、または作業を取りやめて、脅威そのものをなくす
- **転嫁**（移転）: 保険や契約で、影響を第三者に移す
- **軽減**: 発生確率や影響度を下げる
- **受容**: 特に対策をとらず、リスクを受け入れる

品質では、品質基準に照らして成果物を検査し、**検査報告書**にまとめる。分析にはQC七つ道具を使う。

| 図 | 見方 | 目的 |
| --- | --- | --- |
| パレート図 | 不良原因などの項目を件数の多い順に並べ、累積比率を重ねる | 重点的に取り組む対象を見つける |
| 管理図 | 時系列のデータが管理限界の内側に収まっているかを見る | 工程の異常やばらつきを検知する |

調達では、外部から購入するものを計画し、供給者を選定し、契約を運営管理する。

コミュニケーションでは、ステークホルダごとに必要な情報を、どの方法で配布するかを決める。

- **プッシュ型**: 送り手が受け手に届ける（電子メール、ボイスメールなど）
- **プル型**: 受け手が必要なときに取りに行く（Webサイトや共有場所）
- **双方向**: その場でやり取りする（会議、テレビ会議など）

## 試験での問われ方

- クリティカルパスの日数と、特定の作業の遅れが全体に影響するかを問う計算が頻出。**経路ごとに日数を足して最長を選ぶ**
- EVMはSV・CVの符号の意味（**負が悪い**）と、EV・PV・ACのどれとどれを比べるかが問われる。EACの計算も出る
- 手法の役割を入れ替えた選択肢が多い。**WBSは作業の分解**、PERTは順序とクリティカルパス、ガントチャートは期間と進捗、クラッシングは費用をかけた期間短縮。回帰分析や線形計画法は日程計画の技法ではない
- プロジェクト憲章は**立上げの認可**、ベースラインは承認済みの計画。プロジェクトは有期性と独自性をもち、「反復して行う定常業務」は誤りの選択肢になる
- リスク対応の具体例（**保険加入は転嫁**、作業を取りやめるのは回避）を判断させる
- パレート図（重点の把握）と**管理図**（ばらつきの監視）の使い分けが問われる

## 用語集

- **プロジェクト**: 独自の成果物を生み出すために行う、始まりと終わりがある有期の活動。
- **プロジェクトマネジメント**: プロジェクトの要求を満たすために知識・技能・手法を適用する活動。
- **プロジェクトガバナンス**: 組織がプロジェクトを方向付け、監督し、説明責任を果たす仕組み。
- **プロジェクトライフサイクル**: 立上げから終結までのプロジェクトの段階の流れ。
- **プロジェクト憲章**: プロジェクトを正式に認可し、目的・概略スコープ・プロジェクトマネージャの権限を定める文書。
- **ベースライン**: 承認されたスコープ・スケジュール・コストの計画。進捗や変更を測る基準になる。
- **得た教訓**: プロジェクトで学んだ成功要因や失敗要因を記録し、次に生かす情報。
- **ステークホルダ**: プロジェクトに影響を与える、または影響を受ける個人や組織。
- **スコープ**: プロジェクトで生み出す成果物と、そのために行う作業の範囲。
- **WBS**: 成果物と作業を階層的に分解した構成図。見積りや担当割当ての基礎。
- **ワークパッケージ**: WBSの最下位の要素。見積り、担当の割当て、進捗管理の単位になる。
- **活動リスト**: WBSから定義した活動（アクティビティ）を一覧にしたもの。
- **ガントチャート**: 作業ごとの開始・終了を横棒で表した工程表。進捗の確認に向くが、依存関係は表しにくい。
- **アローダイアグラム（PERT）**: 作業の依存関係と所要日数を矢線で表した図。クリティカルパスを求める。
- **クリティカルパス**: 開始から終了までの経路のうち最も所要日数が長い経路。余裕がない。
- **クラッシング・ファストトラッキング**: 資源を追加して期間を縮める方法（費用が増える）と、作業を並行して進めて期間を縮める方法（手戻りのリスクが増える）。
- **コストベースライン**: 承認された時系列の予算。コスト管理の基準。
- **EVM**: PV・EV・ACを比較して進捗とコストを定量的に管理する手法。
- **PV・EV・AC**: 計画価値、出来高（完了した作業の予算換算額）、実コスト。
- **SV・CV・SPI・CPI**: スケジュール差異（EV－PV）とコスト差異（EV－AC）、およびそれぞれの比率（EV÷PV、EV÷AC）。差異は負、比率は1未満が悪い状態。
- **リスクの特定・評価・対応・管理**: リスクを洗い出し、確率と影響で評価し、対応策を決め、監視する一連のプロセス。
- **リスク登録簿**: 特定したリスクと、その評価、対応策、担当者などを記録して管理する文書。
- **回避・転嫁・軽減・受容**: 脅威に対する4つのリスク対応戦略。
- **検査報告書**: 成果物が品質基準を満たしているかを検査した結果をまとめた文書。
- **パレート図**: 項目を件数順に並べ累積比率を重ねた図。重点的に取り組む対象を見つける。
- **管理図**: 時系列データが管理限界内に収まっているかを見て、工程の異常を検知する図。
- **調達**: 外部から製品やサービスを購入する活動。計画、供給者の選定、契約の運営管理を含む。
- **プッシュ型・プル型コミュニケーション**: 送り手が情報を届けるのがプッシュ型、受け手が取りに行くのがプル型。
- **双方向コミュニケーション**: 会議やテレビ会議のように、その場でやり取りできる情報交換。
- **回帰分析・時系列分析・線形計画法**: 変数間の関係やデータの推移から将来を予測する統計手法と、制約の下で最適な資源配分を求める手法。いずれも日程計画の技法ではない。
