## 要点

- 国の司令塔は**サイバーセキュリティ戦略本部**で、その事務局だった内閣サイバーセキュリティセンター（NISC）は2025年7月1日に国家サイバー統括室へ改組された
- **IPA**（セキュリティセンター）は情報セキュリティ10大脅威の公表、ウイルス・不正アクセス・脆弱性の届出受付、J-CSIP・J-CRATの運営を担う
- **JPCERT/CC**は国内のインシデント対応の調整役で、早期警戒情報の発信やCSIRTマテリアルの提供を行い、IPAとともにJVNを運営する
- **CRYPTREC**は電子政府で使う暗号技術の安全性を評価・監視して暗号リストを公表し、JIPDECはプライバシーマーク制度を運営する
- CSIRTは組織のインシデント対応窓口、**SOC**は監視の専門組織、ISACは業界内の情報共有組織で、役割が異なる
- **サイバー保険**は損害の金銭的な補償によるリスク共有の手段であり、攻撃そのものを防ぐものではない

## 解説

### 国の体制

サイバーセキュリティ基本法に基づき、2015年1月、内閣に**サイバーセキュリティ戦略本部**が置かれ、同時に内閣官房に内閣サイバーセキュリティセンター（**NISC**）が設置された。戦略本部は、国のサイバーセキュリティ戦略の策定や、政府機関等の情報セキュリティ対策のための統一基準群の決定を行い、NISCはその事務局を務めてきた。

NISCは、2025年に成立したサイバー対処能力強化法などを受けて、2025年7月1日に内閣官房の**国家サイバー統括室**へ改組された。国家サイバー統括室は、政府全体のサイバーセキュリティ政策の総合調整に加え、官民連携や能動的サイバー防御に関する業務を担う。

基本法の改正で設けられたサイバーセキュリティ協議会は、官民の関係者が機密を保ちながら情報を共有する枠組みである。

### IPAの役割

**IPA**（情報処理推進機構）のセキュリティセンターは、対策の普及、脅威情報の収集・分析、各種制度の運営を行う。

- **情報セキュリティ10大脅威**: 前年に注目された脅威を「組織」と「個人」に分けて順位付けし、毎年公表する資料
- **届出制度**: コンピュータウイルス届出制度とコンピュータ不正アクセス届出制度の届出先となり、被害の傾向を公表する
- **ソフトウェア等の脆弱性関連情報に関する届出制度**: 発見者からの届出をIPAが受け付け、製品の脆弱性はJPCERT/CCが製品開発者と調整し、Webサイトの脆弱性はIPAがサイト運営者に通知する。この官民の枠組みを情報セキュリティ早期警戒パートナーシップという
- **J-CSIP**（サイバー情報共有イニシアティブ）: 重要インフラ関連企業が参加し、標的型攻撃などの情報をIPAを介して共有する枠組み
- **J-CRAT**（サイバーレスキュー隊）: 標的型攻撃の被害を受けた組織からの相談を受け、被害の拡大防止を支援する活動
- **情報セキュリティサービス基準と審査登録制度**: 監査、脆弱性診断、デジタルフォレンジック、監視・運用の各サービスの基準を経済産業省が定め、審査登録機関が審査し、適合サービスリストをIPAが公開する
- **ISMAP**: 政府が求めるセキュリティ要求を満たすクラウドサービスを登録し、政府機関がそのリストから調達する制度。IPAが運用支援を行う（新制度で追加: クラウドの観点）

### JPCERT/CC・JVN・CRYPTRECなどの機関

**JPCERT/CC**（JPCERTコーディネーションセンター）は、国内のインシデント報告を受け付け、関係者との調整を行う民間の非営利組織である。深刻な脆弱性や攻撃について注意喚起や早期警戒情報を発信し、CSIRTマテリアルでCSIRTの構築を支援する。

**JVN**（Japan Vulnerability Notes）は、IPAとJPCERT/CCが共同で運営する脆弱性対策情報ポータルサイトで、国内製品の脆弱性と対策、CVSSによる深刻度を公開する。

**CRYPTREC**は、総務省と経済産業省が、NICT（情報通信研究機構）・IPAとともに運営するプロジェクトである。電子政府での利用を推奨する暗号技術の安全性を評価・監視し、実装や運用の方法も検討して、電子政府推奨暗号リストを含むCRYPTREC暗号リストを公表する。

**暗号装置の輸出許可の審査、IT製品のセキュリティ評価・認証、企業のサーバへの攻撃の監視は、CRYPTRECの役割ではない**。輸出許可は外為法（外国為替及び外国貿易法）に基づき経済産業省が審査し、IT製品の評価・認証はISO/IEC 15408に基づくJISEC、攻撃の監視はSOCなどが担う。

このほか、次の機関や取組みがある。

- **JIPDEC**（日本情報経済社会推進協会）: 個人情報を適切に取り扱う事業者を認定するプライバシーマーク制度を運営する
- **ISMS-AC**: ISMS適合性評価制度で認証機関を認定する認定機関
- **NOTICE**: 総務省とNICTが、パスワード設定の弱いIoT機器を調査して利用者に注意喚起する取組み

### 主な資料と作成した組織

資料名と、それを作成・公開した組織の組合せも問われる。

| 資料 | 作成した組織 | 内容 |
| --- | --- | --- |
| CSIRTマテリアル | JPCERT/CC | 組織内CSIRTの構築と運用を支援する資料。構想・構築・運用の段階ごとにまとめている |
| 情報セキュリティ10大脅威 | IPA | 前年に注目された脅威の順位 |
| 組織における内部不正防止ガイドライン | IPA | 内部不正対策の考え方と対策例 |
| 中小企業の情報セキュリティ対策ガイドライン | IPA | 中小企業向けの対策の進め方 |
| サイバーセキュリティ経営ガイドライン | 経済産業省・IPA | 経営者が認識すべき原則と指示すべき事項 |
| 証拠保全ガイドライン | デジタル・フォレンジック研究会（IDF） | インシデント発生時の電子的証拠の保全手順 |
| ISMSユーザーズガイド | JIPDEC | JIS Q 27001の要求事項を解説した、ISMS構築のための手引 |

### 組織内のセキュリティ組織と情報共有

組織内では、役割の異なる次のような組織が置かれる。

| 組織 | 役割 |
| --- | --- |
| 情報セキュリティ委員会 | 全社の方針を決める |
| CSIRT | インシデント対応の窓口と、関係者との調整を担う |
| SOC（Security Operation Center） | ログやネットワークを常時監視して攻撃の兆候を検知し、CSIRTに引き継ぐ |
| PSIRT | 自社の製品やサービスの脆弱性に対応する |

**エシカルハッカー**は、許可を得たうえで攻撃者の手法を使ってシステムの弱点を見つけ、改善に役立てる技術者を指す。

**ISAC**（Information Sharing and Analysis Center）は、金融、ICT、電力など業界ごとに設けられ、会員企業間で脅威情報や対策を共有する。J-CSIPも同じ目的の枠組みである。IPAやJPCERT/CCが発表する再発防止のための提言や、毎年2月から3月のサイバーセキュリティ月間などの啓発活動も、意識を高める機会として活用したい。

### サイバー保険

**サイバー保険**は、サイバー攻撃による損害賠償、調査・復旧費用、事業中断による損失などを補償する保険である。リスク対応の分類ではリスク共有（移転）、つまりリスクファイナンシングの手段に当たる。

損失を金銭的に補うだけで、攻撃や漏えいを防ぐ効果はなく、信用の失墜は補償されない。管理策によるリスク低減を行ったうえで、残留リスクへの備えとして組み合わせるのが正しい位置付けである。

## 試験での問われ方

- 各機関の役割や、資料と作成元の組合せを入れ替えた選択肢が頻出。10大脅威・届出受付・J-CSIP・J-CRATはIPA、インシデント調整・早期警戒・**CSIRTマテリアル**はJPCERT/CC、暗号評価はCRYPTREC、プライバシーマークはJIPDEC
- JVNは「**IPAとJPCERT/CCの共同運営**」の脆弱性対策情報ポータル。脆弱性届出制度では、製品は「IPAが受付、JPCERT/CCが開発者と調整」、Webサイトは「IPAが運営者に通知」という分担が問われる
- NISCは2015年に戦略本部と同時に**内閣官房**に設置され、2025年7月に国家サイバー統括室へ改組された。「内閣サイバーセキュリティセンター」の名称で出題されたら旧名称として読み替える
- CRYPTRECは「電子政府推奨暗号の**安全性の評価・監視**」。輸出許可の審査、IT製品の評価・認証、攻撃の監視とする選択肢は誤り
- CSIRT（対応の窓口・調整）、**SOC**（監視）、ISAC（業界内の情報共有）の違いを問う
- サイバー保険は「**リスク共有**（移転）」であり、「リスク低減」や「リスク回避」とする選択肢は誤り

## 用語集

- **情報セキュリティ委員会**: 経営層と部門代表で構成し、組織の情報セキュリティの方針や対策を審議・決定する機関。
- **CSIRT**: 組織内でインシデントの受付、対応、関係者との調整を担うチーム。
- **PSIRT**: 自社の製品やサービスの脆弱性に対応する専門チーム。
- **SOC（Security Operation Center）**: ログやネットワークを常時監視し、攻撃の兆候を検知して通知する専門組織。
- **エシカルハッカー**: 許可を得て攻撃者の手法でシステムの弱点を探し、防御の改善に役立てる技術者。
- **サイバーセキュリティ戦略本部**: サイバーセキュリティ基本法に基づき内閣に置かれ、国の戦略や政府機関の統一基準を決定する本部。
- **内閣サイバーセキュリティセンター（NISC）**: 2015年に内閣官房に設置され、戦略本部の事務局として活動した組織。2025年7月1日に国家サイバー統括室へ改組された。
- **国家サイバー統括室**: NISCを改組して内閣官房に設置された、政府のサイバーセキュリティ政策の総合調整と官民連携を担う組織。
- **IPAセキュリティセンター**: 情報セキュリティ対策の普及、脅威情報の分析、届出受付などを行うIPAの部門。
- **情報セキュリティ10大脅威**: IPAが毎年公表する、組織・個人それぞれで注目された脅威の順位。
- **CRYPTREC**: 電子政府で利用を推奨する暗号技術の安全性を評価・監視し、CRYPTREC暗号リストを公表するプロジェクト。
- **JPCERTコーディネーションセンター**: 国内のインシデント報告の受付と調整、早期警戒情報の発信を行う組織。
- **CSIRTマテリアル**: JPCERT/CCが公開している、組織内CSIRTの構築と運用を支援する資料。
- **J-CSIP（サイバー情報共有イニシアティブ）**: 重要インフラ関連企業がIPAを介して標的型攻撃などの情報を共有する枠組み。
- **JVN（Japan Vulnerability Notes）**: IPAとJPCERT/CCが共同運営する脆弱性対策情報のポータルサイト。
- **Trusted Web推進協議会**: インターネット上のデータの信頼性を高める仕組みを検討するため内閣官房が設置した協議会。
- **コンピュータ不正アクセス届出制度・コンピュータウイルス届出制度**: 不正アクセスやウイルスの被害をIPAに届け出る制度。
- **ソフトウェア等の脆弱性関連情報に関する届出制度**: 発見した脆弱性をIPAに届け出る制度。製品はJPCERT/CCが開発者と調整する。
- **情報セキュリティ早期警戒パートナーシップ**: 脆弱性情報の届出から公表までを官民で連携して進める枠組み。
- **情報セキュリティサービス基準・審査登録制度・適合サービスリスト**: 監査・脆弱性診断・フォレンジック・監視運用サービスの基準と審査制度。適合サービスをIPAが公開する。
- **ISMAP**: 政府が求める要求を満たすクラウドサービスを登録し、政府機関が調達に用いる制度。
- **サイバーレスキュー隊（J-CRAT）**: 標的型攻撃の被害組織からの相談を受け、被害拡大の防止を支援するIPAの活動。
- **NOTICE**: 総務省とNICTが、パスワード設定の弱いIoT機器を調査して利用者に注意喚起する取組み。
- **SECURITY ACTION**: 中小企業が情報セキュリティ対策への取組みを自ら宣言するIPAの制度。
- **ISAC**: 業界ごとに設けられ、会員企業間でセキュリティ情報を共有・分析する組織。
- **JIPDEC（プライバシーマーク）**: 個人情報を適切に取り扱う事業者を認定するプライバシーマーク制度を運営する機関。
- **ISMS適合性評価制度**: ISMSがJIS Q 27001に適合するかを第三者が審査・認証する制度。認定機関はISMS-AC。
- **再発防止のための提言**: 発生したインシデントの原因と対策をまとめ、他の組織の被害防止に役立てる提言。
- **情報セキュリティに関する啓発活動**: サイバーセキュリティ月間や講習会、資料配付などで意識向上を図る活動。
- **サイバー保険**: サイバー攻撃による賠償や復旧費用などを補償する保険。リスク共有（移転）の手段。
