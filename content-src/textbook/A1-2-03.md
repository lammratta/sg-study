## 要点

- 情報セキュリティポリシーは「基本方針（なぜ守るか）→対策基準（何を守るか）→実施手順（どう守るか）」の3階層で構成し、**基本方針**は経営層が承認して社内外に公開する
- 情報は**機密区分**に分けてラベル付けし、区分ごとに開示範囲・保管・廃棄の方法を決める。ラベル付けは「知らなかった」という言い訳も封じる
- **情報セキュリティ管理基準**はマネジメント基準と管理策基準からなる組織の実施基準、情報セキュリティ監査基準は監査人の行動規範で、どちらも経済産業省が定める
- 経営者向けの**サイバーセキュリティ経営ガイドライン**は3原則と重要10項目を示す。中小企業向けにはIPAの対策ガイドラインと、自己宣言制度のSECURITY ACTION（一つ星・二つ星）がある
- 組織における内部不正防止ガイドラインは、状況的犯罪予防に基づく**5つの基本原則**で内部不正を防ぐ
- 情報セキュリティ委員会が全社の方針を決め、**CISO**が統括し、各部門の情報セキュリティリーダーが現場で実践する

## 解説

### 情報セキュリティポリシーの3階層

**情報セキュリティポリシー**は、組織が情報セキュリティにどう取り組むかを文書にした規程の体系で、一般に3階層で構成する。

| 階層 | 内容 | 決定者と公開範囲 |
| --- | --- | --- |
| 基本方針（情報セキュリティ方針） | 組織の目的、基本的な考え方、経営者の責任を宣言する | 経営層が承認し、社内外に公開する |
| 対策基準 | 基本方針を実現するために守るべき基準を分野ごとに定める | 情報セキュリティ委員会などが定め、原則社内限り |
| 実施手順 | 対策基準を実行するための具体的な手順やマニュアル | 各部門・システムごとに作成する |

基本方針は抽象的で変わりにくく、実施手順は技術や組織の変化に合わせて頻繁に更新される。**基本方針に具体的な製品名や設定値を書くのは不適切**である。策定後は情報セキュリティ目的を設定し、周知・点検・見直しを続ける。

### 組織内規程の種類

対策基準や実施手順の下には、目的別の規程が置かれる。

- **情報管理規程・秘密情報管理規程**: 情報の分類と、持出しなどの取扱いを定める
- **文書管理規程**: 文書の保管と廃棄を定める
- **情報セキュリティインシデント対応規程**: マルウェア感染時などの連絡先と手順を定める
- **情報セキュリティ教育の規程**: 教育の対象と頻度を定める
- **職務規程・罰則の規程**: 役割と責任、違反時の懲戒を定める
- **対外説明の規程**: 事故発生時の広報の窓口を決める
- **例外の規程**: 基準を守れないときの申請と承認の手続を定める
- **規則更新の規程・規程の承認手続**: 規程の改定と承認の手続を定める

対外的な文書として、個人情報の利用目的や問合せ窓口などを本人に示す**プライバシーポリシー**（個人情報保護方針）がある。従業員の私的な発信による情報漏えいを防ぐため、SNS利用のルールを定めた**ソーシャルメディアガイドライン**（SNS利用ポリシー）も重要になっている。

例外の規程に従って申請し、代わりの対策と対応の時期を明らかにして承認を得た場合は、規程に沿った対応として扱われる。**手続を経ずに基準を守らないことが違反**であり、点検ではこの区別を確かめる。

### 情報の分類とラベル付け

情報は重要度に応じて**機密区分**に分け、文書やファイルにその区分を表示する（**ラベル付け**）。区分の名前や数は組織ごとに決め、例えば「極秘」「社外秘」「公開」のように段階を設ける。JIS Q 27002でも、情報の分類とラベル付けは組織的管理策に含まれる。

区分ごとに、次のような取扱いを規程で決めておく。

| 取扱い | 決めておく内容の例 |
| --- | --- |
| 開示範囲 | 誰に見せてよいか（役員だけ、特定の部署だけ、社内全体など） |
| 表示（ラベル付け） | 文書のヘッダーやファイル名に、区分と開示範囲を明記する |
| 保管 | 施錠できるキャビネットに保管し、離席時も机上に放置しない（クリアデスク） |
| 廃棄 | 紙はシュレッダーで細断し、媒体は復元できない方法で処分する |

ラベル付けをしておけば、扱う人が区分を一目で判断でき、取扱いの誤りを防げる。さらに、持出し禁止などのルールを周知したうえでラベルを付けておけば、不正に持ち出した者に「重要な情報とは知らなかった」という言い訳をさせない効果もある。

開示してよいかは、**いまの業務でその情報を知る必要があるか**（need-to-know）で判断する。以前その情報を扱う部署にいた人や、別の業務の参考にしたい人であっても、現在の開示範囲に入っていなければ見せてはいけない。

### 推進体制と役割

- **情報セキュリティ委員会**: 経営層や各部門の代表で構成され、ポリシーの策定・改定、重要なリスク対応、インシデントの報告を審議する全社的な意思決定機関
- **CISO**（最高情報セキュリティ責任者）: 経営層の一員として情報セキュリティを統括し、経営者に説明責任を負う。情報セキュリティの計画や、基準の例外のような重要な判断に責任をもつ
- **情報セキュリティリーダー**: 利用部門に置かれる現場の責任者。部門内の情報資産の把握、ルールの周知、従業員からの相談や報告の受付、自己点検、インシデント発生時の初動と上位への報告を担う

### 情報セキュリティ管理基準と懲戒手続

**情報セキュリティ管理基準**は、組織が実施すべきことを、JIS Q 27001・27002に対応する形でまとめた基準である。ISMSを構築・運用するための**マネジメント基準**（JIS Q 27001に対応）と、個々の管理策を示す**管理策基準**（JIS Q 27002に対応）の2つで構成される。

**情報セキュリティ監査基準**は、監査人が守るべき行動規範と監査の手順を定めたもので、管理基準とともに情報セキュリティ監査制度の柱である。監査では、管理基準に照らして規程や運用を確かめ、基準に反する点を指摘事項として報告する。

管理策基準には、人的な管理策として**懲戒手続**についての事項も含まれる。JIS Q 27002の考え方に沿って、次のことが求められる。

- 懲戒手続を正式に定め、従業員に周知する
- **違反が実際に起きたことを確かめてから手続を始める**。違反の可能性に気付いただけで、ただちに処分を始めることはしない
- 違反の性質と重大さ、業務への影響、初めてか繰り返しか、教育を受けていたかなどを考えて、段階的に対応する
- 違反を疑われた人を、公正かつ公平に扱う

### 経営者・中小企業向けのガイドライン

**サイバーセキュリティ経営ガイドライン**は、経済産業省とIPAが経営者向けに策定したものである。経営者が認識すべき3原則は次のとおりである。

- 経営者がリーダーシップをとって対策を進める
- 自社だけでなく、サプライチェーン全体に目配りする
- 平時と緊急時のいずれでも、関係者と適切にコミュニケーションをとる

あわせて、CISOなどに指示すべき**重要10項目**（方針策定、管理体制、資源確保、リスク把握、インシデント対応・復旧体制、サプライチェーン対策、情報共有など）を示している。

**中小企業の情報セキュリティ対策ガイドライン**は、IPAが中小企業向けに策定したもので、経営者編と実践編からなる。「情報セキュリティ5か条」と「5分でできる！情報セキュリティ自社診断」を用意している。

**SECURITY ACTION**は、中小企業が対策への取組みを自ら宣言する制度である。5か条に取り組む一つ星と、自社診断を行って基本方針を定め公開する二つ星がある。**第三者の審査はなく自己宣言である**点が、認証制度との違いである。

### 内部不正防止ガイドライン

**組織における内部不正防止ガイドライン**はIPAが策定したもので、状況的犯罪予防の考え方に基づく5つの基本原則で対策を整理している。

| 基本原則 | ねらい | 対策の例 |
| --- | --- | --- |
| 犯行を難しくする | 不正をやりにくくする | アクセス権の最小化、電子化した文書へのアクセス制御、外部送信や持出しの制限 |
| 捕まるリスクを高める | やれば見つかると思わせる | ログの取得と監視、監視していることの周知 |
| 犯行の見返りを減らす | やっても割に合わないようにする | 重要情報の暗号化、不要な情報の消去 |
| 犯行の誘因を減らす | 不正をする気を起こさせない | 公平な人事評価、働きやすい職場環境と信頼関係 |
| 犯罪の弁明をさせない | 言い訳を許さない | ルールの周知と誓約書、機密区分のラベル付け |

不正のトライアングル（機会・動機・正当化）と対応させると、アクセス制限や持出し制限は「機会」を、職場環境の整備は「動機」を減らす対策である。**ルールの周知やラベル付けは「知らなかった」という言い訳を封じ、正当化を防ぐ**対策に当たる。

### その他の基準とフレームワーク

- **コンピュータウイルス対策基準・コンピュータ不正アクセス対策基準**: 被害の予防・発見・復旧と届出の方法を定めた経済産業省の告示
- **ソフトウエア製品等の脆弱性関連情報に関する取扱規程**: 脆弱性の届出と公表の手順を定めた経済産業省の告示
- **政府機関等の情報セキュリティ対策のための統一基準群**: サイバーセキュリティ戦略本部が決定する政府機関向けの基準
- **IoTセキュリティガイドライン**: IoT機器・サービスの企画から運用までの対策の指針
- **サイバー・フィジカル・セキュリティ対策フレームワーク**: 産業分野のサプライチェーンを三層でとらえて対策を整理した経済産業省の枠組み
- **金融機関等コンピュータシステムの安全対策基準・解説書**: FISCが策定した、金融機関向けの安全対策の基準
- **サイバーセキュリティフレームワーク**（CSF）: 米国NISTの枠組み。統治・識別・防御・検知・対応・復旧の機能で対策の全体像を整理し、国際的に参照されている

## 試験での問われ方

- ポリシーの3階層で、各階層に書く内容と公開範囲を問う。「基本方針に具体的な設定値を書く」「実施手順を社外公開する」は誤り。基本方針の**承認者は経営層**で、情報システム部門長や外部の監査人ではない
- SECURITY ACTIONは「**自己宣言**」であり、第三者審査や認証ではない。一つ星と二つ星の条件を入れ替えた選択肢に注意
- サイバーセキュリティ経営ガイドラインの対象は「**経営者**」で、3原則（リーダーシップ、サプライチェーン、コミュニケーション）が問われる。情報セキュリティ管理基準（組織が実施する基準。マネジメント基準と管理策基準からなる）と監査基準（監査人の行動規範）の違いも問われる
- 内部不正対策を5つの基本原則や不正のトライアングルに対応させて問う。**ラベル付け**やルールの周知は「言い訳をさせない（正当化を防ぐ）」対策
- 懲戒手続は「**違反の事実を確かめてから**開始」「段階的」「公正」。可能性に気付いただけでただちに処分を始める規定は、監査で指摘事項になる
- 科目Bでは、規程と事例を一つずつ突き合わせる。**開示範囲**（以前の所属や業務上の参考は理由にならない）、離席時の保管、廃棄方法、承認を得た例外かどうかを照合する

## 用語集

- **情報セキュリティポリシーに従った組織運営**: 基本方針・対策基準・実施手順を定め、周知・点検・見直しを続ける組織の運営。
- **情報セキュリティ方針（基本方針）**: 組織の情報セキュリティに対する考え方と経営者の責任を宣言した最上位の文書。経営層が承認し公開する。
- **情報セキュリティ目的**: 方針に沿って組織が達成しようとする具体的な目標。測定できる形で設定する。
- **情報セキュリティ対策基準**: 基本方針を実現するために守るべき基準を分野ごとに定めた規程。原則社内限り。
- **実施手順**: 対策基準を実行するための具体的な手順やマニュアル。
- **情報管理規程・秘密情報管理規程**: 情報の分類、取扱い、保管、持出しなどのルールを定めた規程。
- **文書管理規程**: 文書の作成・承認・保管・廃棄の手順を定めた規程。
- **機密区分・ラベル付け**: 情報を重要度で「極秘」「社外秘」「公開」などに分け、文書やファイルに区分と開示範囲を表示すること。取扱いの誤りと言い訳を防ぐ。
- **情報セキュリティインシデント対応規程**: マルウェア感染時などの連絡先、初動、報告の手順を定めた規程。
- **情報セキュリティ教育の規程**: 教育の対象、内容、頻度、記録を定めた規程。
- **プライバシーポリシー（個人情報保護方針）**: 個人情報の取扱い方針や利用目的、問合せ窓口を本人に示す対外的な文書。
- **職務規程・罰則の規程**: 役割と責任、および違反時の懲戒を定めた規程。
- **懲戒手続**: 規程に違反した従業員への処分の手続。違反の事実を確かめてから、重大さなどに応じて段階的かつ公正に行う。
- **対外説明の規程**: 事故発生時などに外部へ説明する窓口と手順を定めた規程。
- **例外の規程**: 基準を守れない場合の申請と承認の手続を定めた規程。
- **規則更新の規程・規程の承認手続**: 規程を見直し改定する手順と、承認の手続。
- **ソーシャルメディアガイドライン（SNS利用ポリシー）**: 従業員のSNS利用に関するルール。業務情報の投稿禁止などを定める。
- **情報セキュリティ委員会**: 経営層と部門代表で構成し、ポリシーや重要なリスク対応を審議する全社的な機関。
- **CISO**: 最高情報セキュリティ責任者。経営層の一員として情報セキュリティを統括する。
- **情報セキュリティリーダー**: 利用部門に置かれる現場の責任者。周知、相談受付、初動対応と報告を担う。
- **情報セキュリティ管理基準**: 組織が実施すべきことをまとめた経済産業省の基準。ISMSを構築・運用するためのマネジメント基準（JIS Q 27001に対応）と、個々の管理策を示す管理策基準（JIS Q 27002に対応）からなる。
- **情報セキュリティ監査基準**: 情報セキュリティ監査における監査人の行動規範と手順を定めた基準。
- **サイバーセキュリティ経営ガイドライン**: 経営者が認識すべき3原則と指示すべき重要10項目を示す経済産業省・IPAのガイドライン。
- **中小企業の情報セキュリティ対策ガイドライン**: IPAが中小企業向けに策定したガイドライン。経営者編と実践編からなる。
- **SECURITY ACTION**: 中小企業が情報セキュリティ対策への取組みを自ら宣言する制度。一つ星・二つ星がある。
- **組織における内部不正防止ガイドライン**: IPAが策定した内部不正対策の指針。状況的犯罪予防に基づく5つの基本原則を示す。
- **コンピュータウイルス対策基準・コンピュータ不正アクセス対策基準**: 被害の予防・発見・復旧と届出の方法を定めた経済産業省の告示。
- **ソフトウエア製品等の脆弱性関連情報に関する取扱規程**: 脆弱性の届出と公表の手順を定めた経済産業省の告示。
- **政府機関等の情報セキュリティ対策のための統一基準群**: サイバーセキュリティ戦略本部が決定する政府機関向けの対策基準。
- **IoTセキュリティガイドライン**: IoT機器・サービスの企画から運用までのセキュリティ指針。
- **サイバー・フィジカル・セキュリティ対策フレームワーク**: 産業分野のサプライチェーンを三層でとらえ、対策を整理した経済産業省の枠組み。
- **金融機関等コンピュータシステムの安全対策基準・解説書**: FISC（金融情報システムセンター）が策定した、金融機関の情報システムの安全対策の基準。
- **サイバーセキュリティフレームワーク（CSF）**: 米国NISTの枠組み。統治・識別・防御・検知・対応・復旧の機能で対策を整理する。
