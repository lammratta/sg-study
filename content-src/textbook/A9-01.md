## 要点

- 情報システム戦略は**経営戦略との整合**を最優先に策定し、CIOが責任者となり、情報システム戦略委員会が全社的な観点で審議する
- **エンタープライズアーキテクチャ**（EA）は業務・データ・アプリケーション・技術の4層で現状（As-Is）と理想（To-Be）を整理し、全体最適を図る
- DXは、データ化（デジタイゼーション）と個別業務のデジタル化（デジタライゼーション）を経て、**組織全体と事業の変革**に至る
- 業務プロセス改善はBPR（抜本的な再設計）、BPM（継続的な改善）、ワークフローシステム、**RPA**（定型作業の自動化）を使い分ける。RPAは業務を見直してから全社で管理して導入する
- ソリューションにはSaaS・PaaS・IaaSなどのクラウド、ASP、アウトソーシング、**BPO**、ハウジング・ホスティングがあり、自社の管理範囲が異なる
- 投資対効果は**ROI**＝（効果－投資額）÷投資額で評価し、KGI・KPIで達成状況を測る。廃棄時はデータ消去まで含めて管理する

## 解説

### 情報システム戦略の策定

**情報システム戦略**は、経営戦略の実現に必要な情報システムの方向性と投資の優先順位を定めたものである。**経営戦略との整合が最も重要**で、経営目標を達成するためにどの業務をどう変え、どのシステムを整備するかを示す。

策定と遂行の責任者は**CIO**（最高情報責任者）である。経営層、利用部門、情報システム部門の代表で構成する**情報システム戦略委員会**が、全社最適の観点で戦略を審議・承認する。

全体を整理する手法が**エンタープライズアーキテクチャ**（EA）で、ビジネス（業務）、データ、アプリケーション、テクノロジの4層について現状（As-Is）と理想（To-Be）を描き、その差を埋める計画を立てる。部門ごとの個別最適ではなく、**全社の全体最適**を目指す点がポイントである。

### ITガバナンスとDX

経営者がITの利活用を方向付け、評価し、監督する仕組みを**ITガバナンス**という。デジタル技術で業務や製品、組織文化まで変革する**DX**（デジタルトランスフォーメーション）を推進するには、戦略レベルでの方向付けが欠かせない。

経済産業省のDXレポート2（2020年）は、DXに至る段階を次の3つに整理している。

| 段階 | 内容 | 例 |
| --- | --- | --- |
| デジタイゼーション | アナログ・物理的な情報をデジタルデータにする | 紙の申込書をスキャンしてデータにする |
| デジタライゼーション | 個別の業務や製造工程をデジタル化する | 1つの部署の受付業務をWebフォームとワークフローで電子化する |
| デジタルトランスフォーメーション | 組織横断・全体の業務や製造工程をデジタル化し、顧客起点の価値を生むように事業やビジネスモデルを変革する | 製品の稼働データを全社で活用し、製品の売切りから利用量に応じた課金サービスへ事業の形を変える |

**1つの工程や部署の効率化にとどまればデジタライゼーション、組織横断で全体を変え、事業やビジネスモデルまで変えていればDX**と判断する。

### 業務プロセスの改善

業務を機能別ではなく、顧客に価値を届ける一連の流れとして捉えるのが**プロセス視点**である。業務プロセスの改善や、システム化による業務効率化の手段には次のものがある。

- **BPR**: ビジネスプロセスリエンジニアリング。既存の業務プロセスを抜本的に見直して再設計する
- **BPM**: ビジネスプロセスマネジメント。業務プロセスを可視化・分析して改善し、実行結果を監視して再び見直すサイクルを継続的に回す
- **ワークフローシステム**: 申請から承認までの流れを電子化する。承認状況の可視化と証跡の保存ができる
- **RPA**: ロボティックプロセスオートメーション。人がPCで行う定型的な操作をソフトウェアのロボットに代行させる

BPRが一度の抜本的な改革であるのに対し、BPMは改善を継続する点が異なる。

RPAは、転記や照合など**ルールが決まった繰返し作業**に向き、判断を伴う作業や例外処理の多い業務には向かない。画面や手順が頻繁に変わる業務も、そのたびにロボットの修正が必要になるため向かない。

全社で導入するときは、**現状の業務をそのまま自動化せず、先に業務プロセス全体を可視化して見直す**。部門ごとにばらばらに作ると、管理者の分からないロボット（野良ロボット）が増え、誤処理や停止に気づけなくなる。情報システム部門を含む全社的な推進体制で、ロボットを登録・管理する。

業務を支える代表的なシステムや手法には次のものがあり、業務改善の手法と区別して覚える。

| 名称 | 内容 |
| --- | --- |
| ERP | 生産、販売、会計、人事などの基幹業務の情報を統合して管理し、経営資源の全体最適を図る |
| CRM | 顧客情報を一元管理し、販売からアフターサービス、問合せ対応まで顧客との関係を管理する |
| SCM | 調達、生産、物流、販売の流れを企業の枠を越えて連携させ、在庫の削減やリードタイム（注文から納品までの期間）の短縮を図る |
| MRP | 生産計画と部品表、在庫情報から、必要な資材の量と時期を計算する生産管理の手法 |

コミュニケーションのためのシステム利用では、電子メール、チャット、グループウェア、Web会議を業務の性質に応じて使い分ける。業務における電子メールの利用ルール（誤送信防止、添付ファイルの扱い）も定める。

### ソリューションビジネス

自社でシステムを構築する代わりに、外部のサービスを利用して課題を解決する形態を**ソリューションサービス**という。

| 形態 | 内容 |
| --- | --- |
| クラウドサービス（SaaS・PaaS・IaaS） | ネットワーク経由で利用する。SaaSはアプリケーション、PaaSは実行環境、IaaSは基盤を提供 |
| ソブリンクラウド | データの保管場所や運用を自国の法制度のもとに置き、主権を確保したクラウド |
| ASP | アプリケーションをネットワーク経由で提供する事業者。SaaSの先行形態 |
| アウトソーシング | 業務や運用を外部に委託する |
| BPO | 自社の中核ではない業務を、業務プロセスごと外部の専門企業に委託する |
| ハウジング | 自社の機器を事業者のデータセンターに設置する。設置場所、電源、回線などを借りる |
| ホスティング | 事業者が所有するサーバを借りて利用する |
| SOA | 業務機能をサービスとして部品化し、組み合わせてシステムを構築する考え方 |

**BPO**（ビジネスプロセスアウトソーシング）の対象は、経理、人事、総務、コールセンターなど、自社の中核（コア）ではない業務である。システムの開発・運用だけでなく業務そのものを任せ、自社の経営資源を中核業務に集中させる。

外部サービスを使うと自社の管理範囲は狭まるが、**データの管理責任は利用者に残る**。契約でサービスレベル、データの所在、終了時のデータ返却・消去を定めることが情報セキュリティ上の要点である。

### システム活用の促進と評価

導入したシステムは使われなければ効果が出ない。利用者教育や**普及啓発**で**デジタルリテラシー**を高め、IoT・ビッグデータ・AI（生成AIを含む）などのデジタル技術の有効活用を進める。

ITを使える人と使えない人の間に生じる格差が**デジタルディバイド**で、使いやすい設計と教育で縮める。問合せに自動で応答する**チャットボット**は、利用者の自己解決を助ける。

個人所有の端末を業務に使う**BYOD**は利便性が高い反面、紛失や私的利用時の感染リスクがあるため、ルールと技術的対策（MDMなど）を組み合わせる。

評価では、まず**投資対効果**を分析する。ROI（投資利益率）は、投資によって得られる効果（利益の増加やコストの削減）から投資額を引き、投資額で割って求める。

例題1: 初期投資2,000万円、年間の運用費300万円、年間のコスト削減効果1,100万円のシステムを5年間使う場合、5年間の純効果は（1,100－300）×5＝4,000万円、ROI＝（4,000－2,000）÷2,000＝1.0、つまり100%である。また、回収期間は2,000÷800＝2.5年で、投資回収の目安になる。

複数の情報化投資を、戦略との適合性、期待される効果、リスクなどの観点で評価・分類し、投資全体の配分を最適化する考え方を**ITポートフォリオ**という。

効果の測定には**KGI**（最終目標の達成指標、例: 売上高）と**KPI**（途中経過の指標、例: 問合せ処理件数）、達成に欠かせない要因である**CSF**（重要成功要因）を設定する。運用開始後は次の評価を行い、必要なら情報システムを改修する。

- システム利用実態の調査（利用率、満足度）
- 業務内容や業務フローの変更の有無の把握
- 運用状況の把握と評価

### 情報システムの廃棄

システムには企画・開発・運用・保守・廃棄という**システムライフサイクル**がある。廃棄時には、保存データを確実に消去し、情報機器は記憶媒体を物理的に破壊するか専用ソフトで上書きしてから処分する。

**初期化やファイル削除だけではデータが復元できる**ため、廃棄証明の取得まで含めて管理する。

## 試験での問われ方

- 情報システム戦略は「**経営戦略との整合**」が正答のキーワード。部門の要望を積み上げるだけの策定は誤り
- BPR（抜本的再設計）とBPM（継続的改善）の区別。RPAは**定型・反復の業務**に向き、業務を見直してから全社で管理して導入する。変更や例外の多い業務から始める、部門任せにするのは誤り
- DXの段階は「**個別の工程の効率化か、組織全体と事業の変革か**」で見分ける
- SaaS・ASP・ホスティング・ハウジングの違い（誰の機器か、何を提供するか）と、**BPOは中核でない業務の委託**であることが問われる。略語の似たBPR、BPM、BCP（事業継続計画）と区別する
- ROIや回収期間の計算は、**効果から運用費を引いた純効果**を使う点に注意。BYODはリスクと対策（MDM、利用ルール）をセットで問う
- 廃棄時のデータ消去では「**初期化・削除では不十分**」が判断ポイント。新制度ではクラウドやAI活用の観点が強まる

## 用語集

- **情報システム戦略**: 経営戦略を実現するために情報システムの方向性と投資の優先順位を定めたもの。
- **情報システム戦略委員会**: 経営層と各部門の代表で構成し、情報システム戦略を全社的観点で審議する組織。
- **CIO**: 最高情報責任者。情報システム戦略の策定と遂行に責任をもつ経営層。
- **エンタープライズアーキテクチャ（EA）**: 業務・データ・アプリケーション・技術の4層で組織全体の現状と理想を整理し全体最適を図る手法。
- **ITガバナンス**: 経営者がITの利活用を方向付け、評価し、監督する仕組み。
- **DX**: デジタルトランスフォーメーション。デジタル技術で業務や製品、組織を変革すること。
- **デジタイゼーション・デジタライゼーション**: DXに至る前の段階。アナログ情報のデジタルデータ化と、個別の業務や工程のデジタル化。
- **プロセス視点**: 業務を部門別ではなく、価値を生み出す一連の流れとして捉える見方。
- **BPR**: 業務プロセスを抜本的に見直し、再設計すること。
- **BPM**: 業務プロセスを継続的に分析・改善していく管理活動。
- **ワークフローシステム**: 申請・承認などの業務の流れを電子化し、進捗と証跡を管理するシステム。
- **RPA**: 人がPCで行う定型的な操作をソフトウェアロボットで自動化する技術。
- **ERP・CRM・SCM**: 基幹業務の情報の統合管理、顧客との関係の管理、調達から販売までの供給の流れの管理を行う仕組み。
- **クラウドサービス**: ネットワーク経由で計算資源やアプリケーションを利用するサービス。SaaS・PaaS・IaaSがある。
- **ソブリンクラウド**: データの保管や運用を特定の国・地域の法制度のもとに置き、データ主権を確保するクラウド。
- **ASP**: アプリケーションをネットワーク経由で提供する事業者やサービス形態。
- **アウトソーシング・BPO**: 業務やシステム運用を外部に委託すること。中核ではない業務を業務プロセスごと委託するのがBPO。
- **ハウジング・ホスティング**: 自社機器を事業者施設に置くのがハウジング、事業者のサーバを借りるのがホスティング。
- **SOA**: 業務機能をサービスとして部品化し、組み合わせてシステムを構築する考え方。
- **デジタルリテラシー**: デジタル技術や情報を適切に理解し活用する能力。
- **デジタルディバイド**: ITを使える人と使えない人の間に生じる情報格差。
- **BYOD**: 個人所有の端末を業務に使うこと。利便性と引換えに紛失や感染のリスクがある。
- **チャットボット**: 利用者からの問合せに自動で応答するプログラム。
- **普及啓発**: 利用者にシステムの目的や使い方を周知し、活用を促す活動。
- **投資対効果分析**: 投資額と得られる効果を比較し、投資の妥当性を評価すること。ROIや回収期間で示す。
- **ITポートフォリオ**: 複数の情報化投資を戦略との適合性、効果、リスクなどで評価し、投資配分を最適化する考え方。
- **KGI・KPI**: 最終目標の達成度を測る指標と、その途中経過を測る指標。
- **システム利用実態の調査**: 利用率や満足度を調べ、システムが想定どおり使われているかを評価すること。
- **システムライフサイクル**: 企画・開発・運用・保守・廃棄というシステムの一生。
- **データの消去・情報機器の廃棄**: 廃棄時に記憶媒体を上書き消去または物理破壊し、復元できない状態にすること。
