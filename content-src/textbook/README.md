# content-src/textbook の執筆ガイド

教科書は 1 ページ 1 Markdown ファイル（`<id>.md`）。ページの一覧と範囲は `pages.json` に決めてあり、`id` / `sub`（シラバス小分類）/ `order` / `title` はそれに従う。`scope` に書いた項目をすべて扱う。

## ファイル形式

```markdown
---
id: A1-1-02
title: 脅威の種類と攻撃者
sub: A1-1
order: 2
readingMinutes: 7
updatedAt: 2026-10-27
---
## 要点

- 3〜6 行。試験で問われる結論だけを 1 行ずつ

## 解説

本文（見出し `###` で項目を分け、合計 1,200〜2,000 字）。用語は初出で定義し、仕組み → 目的 → 試験での扱いの順に書く。表は Markdown の表、比較は箇条書き。

## 試験での問われ方

- 3〜6 行。「○○と△△の違いを問う」「〜は誤りの選択肢として頻出」のような、問題を解くときの判断ポイントとひっかけ

## 用語集

- **用語**: 1〜2 文の説明（シラバスの用語例を中心に 12〜30 語）
```

## 書き方のルール

- 対象は情報セキュリティマネジメント試験（SG、レベル 2）の受験者。利用部門の情報セキュリティリーダーが実務で判断できる水準で、深掘りしすぎない
- シラバス Ver.4.1 の該当する小分類の「項目」と「用語例」を網羅する（work/text/syllabus_sg_ver4_1.plain.txt を参照）。用語集にはシラバスの用語例を優先して入れる
- 最新の制度・法令に合わせる: 内閣サイバーセキュリティセンター（NISC）は 2025 年 7 月 1 日に国家サイバー統括室へ改組、プロバイダ責任制限法は 2025 年 4 月 1 日施行で情報流通プラットフォーム対処法に改称、JIS Q 27001 は 2023 年版、JIS Q 27002 は 2024 年版、個人情報保護法は 2022 年 4 月施行の改正（漏えい等報告の義務化、仮名加工情報）を前提にする
- 2027 年度の新制度で追加される観点（データ・AI の利活用、クラウド、AI 倫理、ランサムウェア対策）は該当ページで触れ、「新制度で追加」と明記する
- 表記: 読点は「、」、英数字の前後の半角スペースは入れない（問題文は IPA 表記のままだが教科書は通常の日本語表記）。見出しは `##`（4 つの固定見出し）と `###` のみ
- 他サイト・他書籍の文章を転載しない。自分の言葉で書く。不確かなことは書かない
- HTML は書かない（Markdown のみ）。画像は使わない
- 関連する問題へのリンクはビルドが自動で付けるので書かない

## 読みやすさのルール（2026-10-30 追加）

- 太字は「覚えるべき用語」と「正誤を決める判断基準」にだけ使う。多すぎると目立たなくなるので、1 段落に 2〜3 か所まで
- 要点: 各箇条の中心になる語句を 1 か所だけ太字にする
- 解説:
  - 重要な用語は、その `###` 小見出しの中で最初に出る箇所だけ太字にする。同じ語を何度も太字にしない
  - 試験で正誤を分ける一文（「見られたなら機密性」「〜は誤り」など）は、文ごと太字にしてよい
  - 1 段落は 3 文程度まで。長い段落は分ける
  - 3 つ以上の並列項目は箇条書き、2 つ以上の比較は表にする
  - 箇条書きで用語を説明するときは `- **用語**: 説明` の形にする。ビルドは「## 用語集」の中の行だけを用語として拾うので、解説で使っても用語集には混ざらない
- 試験での問われ方: 各箇条の決め手になる語句を太字にする
- 用語集: 形式は従来どおり `- **用語**: 説明`
- 斜体、取り消し線、HTML、絵文字は使わない

### 太字の書き方の注意（重要）

Markdown の仕様で、太字の内側の先頭や末尾がかっこ・句読点で、外側がふつうの文字だと太字にならず `**` がそのまま表示される。太字の内側の最初と最後の文字は、漢字・かな・英数字にする。

| 書き方 | 結果 |
|---|---|
| `「**見られた**」なら機密性` | 太字になる |
| `**「見られた」**なら機密性` | 太字にならない |
| `**機密性**（C）は` | 太字になる |
| `**機密性（C）**は` | 太字にならない |
| `**パッチ未適用は脆弱性**である。` | 太字になる |

書いたら `node scripts/check-textbook.mjs <ページid…>` で確認する。太字にならない `**`、見出しの欠け、用語集の形式崩れ、長すぎる段落を表示する。

## 確認テストとの対応（2026-10-30 追加）

- 各ページ末尾の「確認テスト」には、`question-map.json` でそのページに割り当てた公式問題だけが出る
- 割当ての基準: そのページと、教科書の並び順（`pages.json` の順）でそれより前のページを読めば、正解を選べること。誤りの選択肢に出てくる用語も、教科書のどこかで説明されていること
- 1 問につき主ページ `page` を 1 つ決める。前提として読むべき前のページがあれば `also` に書く
- 正解に必要な知識が教科書にない場合は、主ページに書き足す

```json
{
  "2023r05-a-04": { "page": "A1-1-05", "also": [] }
}
```
