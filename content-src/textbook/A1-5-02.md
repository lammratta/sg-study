## 要点

- ファイアウォールのルールは、必要な通信だけ許可し最後に全て拒否する**デフォルト拒否**が原則。ルールは上から順に評価され、最初に一致したものが適用される
- **NAT/NAPT**は内部のプライベートIPアドレスを外部に見せない仕組みで、外部からの直接到達を防ぐ副次効果があるが、ファイアウォールの代わりにはならない
- プロキシは「内部から外部」への通信を代理し、**リバースプロキシ**は「外部から内部サーバ」への通信を代理して公開サーバを隠す
- **VLAN**でネットワークを論理的に分割すると、感染や侵入の横展開を抑えられる。認証VLANは認証結果で所属VLANを決める
- IDSは通信のコピーを監視するため経路に影響せず、IPSは**経路上に置いて遮断**する。ハニーポットは囮
- **ポート番号**と対応サービス（22 SSH、23 Telnet、25 SMTP、53 DNS、80 HTTP、443 HTTPS、3389 RDPなど）を覚え、不要なポートは閉じる

## 解説

### ファイアウォールの設計とパケットフィルタリング

**ファイアウォール**は、ネットワークの境界で通信を検査し、通過の可否を決める。**パケットフィルタリング**では、ヘッダにある送信元・宛先のIPアドレス、プロトコル（TCP/UDP）、ポート番号を条件にルールを書く。

**ルールは上から順に評価され、最初に一致したルールの動作が適用される**ため、順序が重要である。設計の原則は、必要な通信だけを明示的に許可し、最後に「全て拒否」のルールを置く**デフォルト拒否**である。公開WebサーバをDMZに置く場合のルールの例を示す。

| 送信元 | 宛先 | 宛先ポート | 動作 |
| --- | --- | --- | --- |
| 任意（インターネット） | DMZのWebサーバ | 443 | 許可 |
| 内部LAN | DMZのプロキシ | 8080 | 許可 |
| DMZ | 内部LAN | 任意 | 拒否 |
| 任意 | 任意 | 任意 | 拒否（デフォルト） |

**ステートフルインスペクション**を使えば、内部から始めた通信への戻りパケットだけを自動で通せる。

### NAT/NAPT

**NAT**は、内部のプライベートIPアドレスをグローバルIPアドレスに変換する仕組みである。**NAPT**（IPマスカレード）はポート番号も使い、1つのグローバルアドレスを多数の端末で共有する。

外部から内部の端末へ直接接続を始められないという、副次的な防御効果はある。しかし、マルウェアの外向き通信などは防げないため、**NAT/NAPTはファイアウォールの代わりにはならない**。

### プロキシとリバースプロキシ

**プロキシ**（フォワードプロキシ）は、内部の端末に代わってインターネット上のWebサーバへアクセスする中継サーバである。**リバースプロキシ**は逆に、インターネットからのアクセスを受け取って内部のWebサーバへ中継する。

| 種類 | 代理する通信 | 主な効果 |
| --- | --- | --- |
| プロキシ | 内部の端末からインターネットへ | 端末が直接インターネットに出ないため、URLフィルタリング、ログ取得、マルウェア検査を一か所で行える |
| リバースプロキシ | インターネットから内部のWebサーバへ | 公開サーバの実体を隠し、TLSの終端、負荷分散、WAF機能をまとめて担える |

**内部から外部への通信を代理するのがプロキシ、外部から内部サーバへの通信を代理するのがリバースプロキシ**と覚える。

### VLANによるセグメント分離

**VLAN**は、スイッチの設定で1つの物理ネットワークを複数の論理ネットワークに分割する技術で、物理的に配線を分ける必要はない。部門別、サーバ用、来客用のようにセグメントを分け、セグメント間の通信を制限すると、1台が感染しても横展開を抑えられる。

**認証VLAN**は、IEEE 802.1Xなどで端末や利用者を認証し、その結果に応じて所属するVLANを動的に割り当てる仕組みである。未認証の端末を隔離用のVLANに入れることができ、認証にはRADIUSなどの**認証サーバ**を使う。

### VPNの形態

VPNには次の2つの形態がある。

| 形態 | 接続の仕方 | 主な技術 |
| --- | --- | --- |
| **拠点間VPN**（サイト間VPN） | 本社と支社のゲートウェイ同士を常時接続する | IPsecなど |
| **リモートアクセスVPN** | 在宅や外出先の端末から社内ネットワークへ接続する | IPsecまたはSSL-VPN |

VPN装置自体の脆弱性が侵入口になる事例が多く、**装置の更新と多要素認証**が必須である。

### IDS/IPSの配置とネットワーク監視

**IDS**（侵入検知システム）は攻撃を検知して知らせる仕組み、**IPS**（侵入防止システム）は検知した攻撃を遮断する仕組みで、置き方と誤検知の影響が異なる。

| 観点 | IDS | IPS |
| --- | --- | --- |
| 置き方 | スイッチのミラーポートなどで通信のコピーを受け取る（経路外） | 通信経路上（インライン）に置く |
| 攻撃への対応 | 検知して通知するだけで、攻撃は止められない | 検知と同時に遮断する |
| 誤検知の影響 | 通信経路に影響しないため、業務は止まらない | 正常な通信の遮断につながる |

配置はファイアウォールの内側が一般的である。**ホスト型IDS**（HIDS）はサーバに導入し、そのサーバへの攻撃や改ざんを検知する。

**ネットワーク監視**では、通信量や通信先の変化を継続的に観察し、SIEMで他のログと突き合わせる。**ハニーポット**は、意図的に脆弱に見せた囮で、攻撃者の手口を観察する。

### 無線LANとMACアドレスフィルタリング

無線LANでは、WPA3またはWPA2（AES）による暗号化と、企業ではIEEE 802.1X認証を行う。

**MACアドレスフィルタリング**は、許可した機器のMACアドレスだけ接続を認める機能である。しかし、**MACアドレスは暗号化されずに電波上を流れ、容易に書き換えられるため、単独の対策にはならない**。SSIDのステルス化も同様に、補助的な効果にとどまる。

### DNSのセキュリティ

名前解決では、利用者の端末が**キャッシュDNSサーバ**に問い合わせる。キャッシュDNSサーバは答えを持っていなければ、利用者に代わって権威DNSサーバへ順にたずね、最終的な答えを返す。

利用者からの「最終的な答えまで調べて返してほしい」という問合せを**再帰的問合せ**という。キャッシュDNSサーバが権威DNSサーバへ順にたずねる問合せは、非再帰的（反復）問合せである。

DNSでは、偽の応答でキャッシュを汚染する**DNSキャッシュポイズニング**や、権威DNSサーバへの大量問合せによるDoSが脅威である。対策には次のものがある。

- **外部からの再帰的問合せを受け付けない**: 内部の利用者からの再帰的問合せだけを受け付ける。誰からでも受け付ける状態を**オープンリゾルバ**といい、攻撃者が好きなときに問合せを起こせるため、ポイズニングやDoSの踏み台に使われる
- **送信元ポート番号とトランザクションIDのランダム化**: 偽の応答は、問合せの送信元ポート番号と、問合せを識別するトランザクションIDの両方が一致しないと受け入れられない。両方を予測できない値にするほど偽造が難しくなり、**固定すると偽の応答を作られやすくなる**
- 応答の署名を検証する**DNSSEC**を使う

キャッシュDNSサーバから権威DNSサーバへの問合せは、もともと非再帰的問合せで行うものなので、それ自体は対策にならない。待ち受けポートを53番に固定することも対策にはならない。

### ポート番号と代表的なサービス

**ポート番号**はサービスの入口であり、**使わないポートを閉じる**ことが基本である。代表的なものは次のとおり。

| ポート番号 | サービス |
| --- | --- |
| 20・21 | FTP（データ転送・制御） |
| 22 | SSH |
| 23 | Telnet |
| 25 | SMTP（メールの送信・転送） |
| 53 | DNS |
| 80 | HTTP |
| 110 | POP3 |
| 143 | IMAP |
| 443 | HTTPS |
| 587 | サブミッションポート（認証付きのメール送信） |
| 3389 | RDP（リモートデスクトップ） |

RDPやSSHをインターネットに直接公開すると、総当たり攻撃の標的になる。接続はVPN経由に限定する。

## 試験での問われ方

- フィルタリングルールの表を読んで「ある通信が許可されるか」を判断する問題。**ルールの順序**とデフォルト拒否、戻りパケット（ステートフル）に注意
- NAT/NAPTを「ファイアウォールと同等のセキュリティ機能」とする選択肢は誤り。アドレスを隠す効果はあるが、**通信内容の制御はしない**
- プロキシとリバースプロキシの**方向の違い**、IDS（検知のみ、経路外）とIPS（遮断、経路上）の違い
- VLANの目的は「**論理的な分割**による被害の局所化」。物理的に配線を分けなくてもよい点が問われる
- MACアドレスフィルタリングやSSIDステルスは「偽装可能なので不十分」、正解は「**WPA3/WPA2と802.1X認証**」
- ポート番号とサービスの対応（23がTelnet、22がSSH、443がHTTPSなど）と、「**不要なポートは閉じる**」原則

## 用語集

- **パケットフィルタリング**: IPアドレス、プロトコル、ポート番号を条件にパケットの通過・遮断を決める方式。
- **デフォルト拒否**: 明示的に許可した通信以外を全て拒否するファイアウォールの設計原則。
- **ステートフルインスペクション**: 通信の状態を記録し、内部から始めた通信の戻りパケットだけを自動で通す方式。
- **NAT**: プライベートIPアドレスとグローバルIPアドレスを変換する仕組み。
- **NAPT（IPマスカレード）**: ポート番号も変換し、1つのグローバルアドレスを多数の端末で共有する仕組み。
- **プロキシ**: 内部端末の代わりに外部へアクセスする中継サーバ。フィルタリングやログ取得を集中して行う。
- **リバースプロキシ**: 外部からのアクセスを受けて内部サーバへ中継するサーバ。公開サーバを隠し、TLS終端や負荷分散を担う。
- **VLAN**: スイッチの設定で物理ネットワークを論理的に分割する技術。セグメント分離に使う。
- **認証VLAN**: 認証結果に応じて端末の所属VLANを動的に割り当てる仕組み。未認証端末を隔離できる。
- **認証サーバ**: 利用者や端末の認証を集中的に行うサーバ。RADIUSサーバが代表。
- **VPN（仮想私設網）**: 共用回線上に暗号化された仮想的な専用線を作る技術。
- **拠点間VPN**: 拠点のゲートウェイ同士を常時接続するVPN。IPsecのトンネルモードが典型。
- **リモートアクセスVPN**: 個々の端末から社内ネットワークへ接続するVPN。IPsecやSSL-VPNを使う。
- **IDS（侵入検知システム）**: 通信のコピーを監視して攻撃を検知・通知する。遮断はしない。
- **IPS（侵入防止システム）**: 通信経路上に置き、攻撃を検知して遮断する。誤検知は正常通信の遮断になる。
- **ホスト型IDS（HIDS）**: サーバに導入し、そのホストへの攻撃やファイル改ざんを検知するIDS。
- **ネットワーク監視**: 通信量や通信先を継続的に観察し、異常や攻撃の兆候を発見する活動。
- **ハニーポット**: 攻撃者を誘い込んで手口を観察する囮のシステム。
- **MACアドレスフィルタリング**: 登録したMACアドレスの機器だけ接続を許す機能。偽装できるため補助的対策。
- **SSIDステルス**: アクセスポイントがSSIDを通知しない設定。傍受で判明するため効果は限定的。
- **DNSキャッシュポイズニング**: キャッシュDNSサーバに偽の応答を記憶させ、利用者を偽サイトへ誘導する攻撃。
- **オープンリゾルバ**: 誰からでも問合せを受け付けるキャッシュDNSサーバ。DoSの踏み台になるため禁止する。
- **再帰的問合せ**: 利用者がキャッシュDNSサーバに、最終的な答えまで調べて返すよう求める問合せ。外部からは受け付けない設定にする
- **トランザクションID**: DNSの問合せと応答を対応づける識別番号。送信元ポート番号とともにランダム化して、偽の応答を受け入れにくくする
- **DNSSEC**: DNS応答に電子署名を付けて改ざんを検知する仕組み。
- **ポート番号**: TCP/UDPでサービスを識別する番号。22 SSH、23 Telnet、25 SMTP、53 DNS、80 HTTP、443 HTTPSなど。
- **ウェルノウンポート**: 0〜1023番の、代表的なサービスに予約されたポート番号。
